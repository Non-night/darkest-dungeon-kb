## 历史方案：以下推拉空间模型与安全分支尚待复核

本页只讨论怪物侧 `.push` / `.pull`。推拉参数表示与方向上的怪物实体交换数量，不是简单的 rank 格数；体型、size-0 半格站位和归并会改变结果。

## 已确认的无 size-0 基线

- 场上无 size-0 时，`.push 3` 与 `.push 4` 或更大值都把目标推到可达的最后位置；`.pull 3` 与 `.pull 4` 或更大值都把目标拉到可达的最前位置；小于 3 按交换数量处理。
- size >= 2 的怪物通常不能被拉动，即使位移抗性检定成功且没有抵抗气泡；这条不能外推为“大体型不能被推”。
- 大体型仍参与理论交换计算。例：1 号位 size2、3 号位 size1 时，3 号位目标 `.pull 1` 可到 1 号位。

## size-0 的站位、归并与路径影响

1. 对 `in_rank` Rule，size-0 始终按 0 号位判定（常见写法为 `rule_data.float: -1`）；这只是 Rule 值，不等于 UI 或碰撞箱的普通 rank。
2. 场上原无 size-0 时，首次召唤可由 `.summon_rank` 指定其初始位置。
3. size-0 相对常规怪物靠前半个身位；召唤到 4 号位时可理解为 3.5 号位，但仍卡住 4 号位碰撞箱。
4. 场上已有 size-0（包括死亡但尚未消失者）时，再召唤的 size-0 会归并到最靠前的现存 size-0。
5. 推/拉路径途经 size-0 时，实际位移少“途经的 size-0 数量”格；若理论上最后交换单位是 size-0，目标会退到 4 号位方向上可达的最末位置，实际 rank 还取决于目标体型和其他实体排列。

## 先判定时序：何时必须警告用户

只有 size-0 在某条具体 `.push` / `.pull` 的理论判定前已经完成入场，才会影响该次推拉。必须逐条核对调用来源和 code 顺序：饰品/附魔 AWR、同一技能中较早的 `queue false` 召唤，以及更早完成的 spawn 都可能属于前置 size-0；推拉之后才入场的 size-0 不计入该次推拉。时序无法确认时写成未知，不得擅自当成风险已成立。

若确认存在前置 size-0，Agent 必须先明确警告用户推拉结果可能偏离无 size-0 公式，并询问是否需要采用下述更安全写法。安全写法是用户可选方案，不是所有推拉的默认模板。

## 条件性安全击退

若用户选择安全击退，在该 `.push` 理论判定前召唤一个怪物侧 1 号位的 size-0 sentinel。已有和随后归并的 size-0 会集中到最靠前位置；在此条件下，已确认可避免由 size-0 分散位置造成的击退路径偏移。召唤 sentinel 的 Effect 直接写 `.target "performer"`；这是本方案采用的怪物侧召唤目标映射。不要在同一 `queue false` 尾部直接杀死 sentinel：推拉可能在该层结束、`queue true` 开始前才提交，清理时点仍属未知边界。


## 条件性安全拉前：分支规格与适用条件

本页示例用于普通英雄对怪物的单体命中技能，同一技能来源、同一普通 `queue false` 层。怪物侧一号位 size-0 sentinel 必须在第一条 `.pull` 理论判定前完成入场；召唤和已确认晚于位移提交的销毁由调用方提供。这里给出完整的 Effect/Buff 引用闭包和技能数据 Header，不提供独立职业、sentinel 怪物资源或完整 Mod。无前置 size-0 的普通推拉不强制采用此模板。

以下规格来自用户明确给出的 P2/P3 处理树及四格编队补充。模板的分支与概率计算属于组合实现，尚无该完整配置的实机结果；不能将静态校验通过描述成实际落位已经验证。

| 调用方案 | 原始目标 T 的条件 | 检测怪物 E | 后写候选 |
|---|---|---|---|
| P1/P2/P3 | 一号位，或自身 size>=2 | 不需要组成条件 | 所有候选理论失败，目标保持原位 |
| P1 | 其余 size1 目标 | 无 | 原始 pull1 |
| P2/P3 | 二号位 size1 | 无 | 站位门打开后写 pull1，门内合计概率恢复为1 |
| P2 | 三号位 size1 | 一号位 size>=2 | 命中则 pull1，否则保留原始 pull2 |
| P2 | 四号位 size1 | 一号位 size>=3 | 命中则后写 pull1，否则保留原始 pull2 |
| P3 | 三号位 size1 | 无 | 先直接 pull2 |
| P3 | 三号位 size1 | 一号位 size>=2 | 命中则再写 pull1，否则保留前一步 pull2 |
| P3 | 四号位 size1 | 非四号位存在恰好 size2 | 命中则 pull2，否则保留原始 pull3 |
| P3 | 四号位 size1 | 一号位 size>=3 | 命中则最后写 pull1；此阶段在 size2 阶段之后 |

P2 的“四号位、一号位 size>=3”分支在本安全模板中必须用后写 `pull1` 覆盖原始 `pull2`。前提是怪物侧一号位的 size-0 sentinel 已在第一条 `.pull` 理论判定前入场：对 `3+1`，若最后采用的候选仍是 `pull2`，该次拉前自身的两次前进交换会在最后与 0 号位 size-0 换位抵消，四号位目标可能原地不动。

P3 以原始 `.pull 3` 作为示例。该段可替换性来自用户明确确认：P3 整套正确且所用数值本身未触发独立边界时，适用更大整数。若目标设计为拉前 4、5、6 或更大整数，只替换 `KB_P3_ORIGINAL` 的原始 `.pull` 数值即可；二号位、三号位和四号位的后写覆盖、跨侧筛选与阶段清理不依赖该原始数值恰好为 3。场上无 size-0 时，`.pull 3` 与 `.pull 4` 或更大值都拉至可达最前位置。场上存在前置 size-0 时，仍须单独检查拟使用的更大数值是否引入其自身的路径或边界问题；未发现该独立问题时，本模板的门控与覆盖结构继续适用。

## 四格编队与阈值简化

范围为普通怪物占用一至四格、连续且从前方排列；size-0 单独处理，不计入以下体型组成。共有十五种有序组成：`1`、`2`、`1+1`、`3`、`2+1`、`1+2`、`1+1+1`、`4`、`3+1`、`1+3`、`2+2`、`2+1+1`、`1+2+1`、`1+1+2`、`1+1+1+1`。这是空间组成的穷举，不是引擎怪物组合白名单。

- 当前可移动目标确实在三号位时，一号位若 size>=2，就只能是 size2；size3/4 占据前方时，不会存在这个三号位目标。因此 P2/P3 的三号位检测不安装 size>=3 负门。
- 当前目标确实在四号位时，一号位若 size>=3，就只能是 size3；一号位 size4 与该四号位目标不能同时存在。因此检测一号位 size>=3 不安装 size>=4 负门。
- P3 四号位的 size2 分支仍须排除 size3：`3+1` 确实存在，所以该阶段保留 `monsterSize>=2` 的 `+40000` 和 `monsterSize>=3` 的 `-40000`，再配合非四号位目标条件。
- 这些简化只有在目标站位成立与四格连续编队同时满足时才能使用；扫描本身仍是阈值，不是将 `monsterSize` 的通用语义改成相等。

## 跨侧筛选、目标和阶段隔离

所有实际 `.pull` 都写 `.target target`，受拉者始终是技能已选目标 T。H 是英雄施术者，E 是 `target_group` 遍历到的怪物。站位相关 Buff 均使用进攻型 `target_in_rank`：修饰 `move_chance` 时检查 T，修饰跨侧扫描的 `debuff_chance` 时检查 E。普通一至四号位分别使用 `rule_data.float: 0/1/2/3`；不要混用 Rule 的零基值与技能 Header 的站位写法。

本专题不使用 `target_enemy_rank` 或 `.clear_rank_target` 控制位移。用户指出该目标类型在本专题推拉组合中存在问题，具体触发表现与底层原因未提供。这里据此采用 Rule 概率门，不据此否定其他调用场景的已有站位检测语义。站位不匹配时，本例 `.target target` 的 Effect 仍进入对应命中时序，由负位移概率关闭候选；不能称为整条 Effect 彻底不发生。

### 原始候选与直接站位覆盖

- **BEGIN → ORIGINAL**：先清旧状态并安装 `BLOCK_R1`、`BLOCK_LARGE`；原始 `.pull 1/2/3` 按 `.chance 1` 判定。此时不能持有本例正的 RANK 或 MOVE 门，否则原始概率会被抬高。
- **RANK_R2_PREP → PULL1_R2**：P2/P3 在原始候选判定后，先用 `CLEAR_STAGE` 清阶段池，再安装 `RANK_R2`。它为 H 上的 `move_chance +40000`，Rule 为 `target_in_rank`、float=1、非取反。候选 `.target target .chance -39999 .pull 1` 在 T 为二号位时得到 `-39999+40000=1`，其他站位保持 -39999。
- **RANK_R3_PREP → PULL2_R3**：P3 再清除二号位门、安装 `RANK_R3`（float=2），以相同的 -39999 单门公式给三号位 T 写 `pull2`。后续组成阶段另行判断是否再覆盖为 `pull1`。
- P1 没有后写站位覆盖，也没有 RANK、MOVE、扫描器或对应清理器；保留 BEGIN、原始 pull1、END 三条 Effect。

### 每个组成检测阶段的六步

1. **INSTALL**：H 用 `CLEAR_STAGE` 删除阶段池中的实际 Buff ID，然后安装本候选的唯一 `RANK_R3` 或 `RANK_R4`（move_chance +40000，分别 float=2/3）及扫描器。三号位分支装 `SCAN_R1 + SCAN_GE2`；四号位的一号位 size>=3 分支装 `SCAN_R1 + SCAN_GE3`。P3 四号位 exact size2 阶段装 `SCAN_NOT_R4 + SCAN_GE2 + SCAN_REJECT_GE3`。
2. **SCAN**：H 通过 `target_group` 向每个 E 尝试施加 `RELAY`。两个正的 debuff_chance 条件都成立时 `-70000+40000+40000=10000`；只满足一个时 -30000，均不满足时 -70000。P3 exact size2 的 `SCAN_REJECT_GE3` 在 E 为 size>=3 时再扣40000，关闭该扫描分支。`SCAN_NOT_R4` 使用 target_in_rank float=3 取反；null 不能靠取反变真，且 size-0 不满足 >=2 正门。该扫描使用阈值 Rule，T 的站位限制在后续位移候选中检查，并不会让整个扫描阶段按 T 的站位跳过。
3. **RETURN**：`target_group + swap_source_and_target true` 令每个 E 向 H 尝试施加 `RESET_MOVE`、`MOVE`。携带 RELAY 的 E 有 `-150000+160000=10000`；未携带者关闭。`RESET_MOVE` 先清旧 MOVE 和自己，再安装一份 always move_chance +40000，避免多次回传叠加；它不清本阶段的 RANK 门。
4. **CLEAN_RELAY**：H 对怪物侧施加具名的 `always` 清理器，只清各 E 自己持有的 RELAY 与清理器自身。H 上的 RANK 和 MOVE 保留给紧随其后的候选。
5. **PULL**：实际目标固定为 T，基础 `.chance -79999`。只有 T 的站位满足 RANK 的 target_in_rank Rule，且组成检测成功回传 MOVE，才得到 `-79999+40000+40000=1`。只满足其中之一为 -39999，均不满足为 -79999。全程 BLOCK_R1/BLOCK_LARGE 继续参与，阻断一号位及大体型 T。
6. **END**：H 的 `CLEAR_STAGE` 直接清除所有 RANK、MOVE、扫描器并自清除，之后才能建立下一阶段。它保留 BLOCK_R1/BLOCK_LARGE；所有候选判定完毕后才由最终 CLEAR_ALL 清除全局阻断及阶段池。

| 候选种类 | Effect 基础 chance | 所需本例正门 | 门都成立时合计 |
|---|---:|---|---:|
| 原始 pull1/2/3 | 1 | 无 | 1 |
| 二号位 pull1、P3 三号位先行 pull2 | -39999 | 匹配站位的 RANK：+40000 | 1 |
| 组成检测后的 pull1/2 | -79999 | 匹配站位的 RANK：+40000；回传 MOVE：+40000 | 1 |

上表数值尚须加外部位移施加率、减目标位移抗性，并接受全局阻断；并非无视位移抗性的保证成功。扫描和回传则用10000保留减益抗性余量；不能把扫描的 -80000 恰好抵为0、或 -79999 抵为1（100%）当成不受减益抗性干扰的必定回传。

不同名称的 move_chance Buff 仍按实际 Rule 一起参与判定，ID 不会指定它只能修饰某条 pull。每次候选窗口只持有一个 RANK 门，组成阶段另可持有一份 MOVE。所有门控的 `remove_if_not_active` 均为 false：Rule 不成立仅使其数值修正不激活，不在扫描其他 E 时自行移除。

清理全部使用 `always` 的具名二段驱散，不依赖 `monsterSize` 条件驱散，也不用等额相反 move_chance 冒充删除。P3 的 size>=3 负 debuff_chance 用于 exact size2 筛选，阶段结束仍须真正清除。清理列表直接包含持有的 Buff ID，不通过一个尚未施加的清理器 ID 间接代清。

极大概率门假定没有外部同等级巨量修正冲破开关间隔。示例沿用同次常规单体技能的概率骰子关系；必要覆盖打开后恢复与原始相同的1，再共同接受外部位移修正与抗性，避免原始成功而覆盖随机失败。扫描和回传通过极大概率取得稳定结果，不依赖怪物回传骰子与英雄位移骰子共享；示例不设置 `.individual_target_actor_rolls true`。

## 时序、证据与未覆盖边界

- **用户明确补充**：P2/P3 分支树、四格组成、三号位/四号位的体型阈值简化、原始 pull3 的更大整数替换范围，以及本专题禁止 target_enemy_rank 控制推拉、改用 target_in_rank Rule Buff 的要求。组合代码仍属本例实现，不声称整套配置已经实机验证。
- **已有社区实测机制**：同一普通 queue false 层按引用顺序判定推拉理论成功，最后一个理论成功候选实际生效；被抵抗候选不占位。实际位移暂存到该层结束与 queue true 之间。见[queue 与 AWR](../../Mechanics/04-queue与AWR.md)、[概率与抗性](../../Mechanics/03-chance与抗性.md)。因此组成检测读取移动前站位，候选判定后的 Buff 清理不会撤销已暂存候选。
- **已有通用清理机制**：[具名二段驱散及 buff_ids 内部顺序](../../Mechanics/25-瞬时效果、正负相抵与二段驱散.md)只清持有者；清理器和重新施加按列表先后处理。

- **实现推断与校验范围**：本页代码和校验器验证引用闭包、实际 Rule/目标解析、门控算式、十五种编队全部目标的候选顺序、阶段清理和重复调用。静态模型不模拟引擎的 size-0 交换路径，不构成最终落位或完整实机时序证明。
- **未知/不支持**：AOE、随机目标、反击、ActorDot、跨来源 AWR、同层定身或其他后写推拉插入、尸体与空洞、超过四格或非标准体型、链中途异常终止。sentinel 保留至实际位移提交及相关依赖完成之后；其销毁时点不得仅由同层 Buff END 推导。
- `target_enemy_rank` 的独立语义与本例禁用边界见[站位检测语义](../../Mechanics/91-target_enemy_rank站位检测语义.md)。本例所有实际位移都使用 target，全部站位限制由 target_in_rank Rule Buff 参与概率判定。
