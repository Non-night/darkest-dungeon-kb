.control
# 分类
扩展/专项字段
# 参数类型
数值（整数/小数及单位以参数说明为准）
# 参数约束
- 参数是单个数字；原版使用整数表示持续轮数。
- 该数值用于表示心控持续的战斗整轮数，不应按个人小回合理解。
# 固定值 / 参数候选
- 无固定候选表；按下方参数说明填写。
# 语义
- `.control <rounds>`：使目标进入心控，并持续指定数量的战斗整轮。
# 作用范围
- Effect 定义行；实际作用对象由调用方目标与 `.target` 等字段共同决定。
- 可能被技能、饰品触发器、ActorDot、spawn、hp_reaction、奇物等系统引用。
# 引擎行为（重要）
- 原版确认：游戏本体或官方 DLC 的 effect 定义直接使用该字段。
- 详见：[Mechanics/22-心控机制.md](../../Mechanics/22-心控机制.md)
- `.control 2` 表示持续 `2` 个战斗整轮，而不是 `2` 个个人小回合。
- 心控目标为英雄；对怪物使用时无效。
- 无动画翻页若写在官方移动技能中，不会出现上述心控卡死问题，因为官方 AI 不可能调用官方移动技能，不会满足“AI 实际调用该类技能”的触发条件。当前用户于2026-11-03明确补充；非本轮新增实机测试。本项针对官方 AI 与官方移动技能，不据此扩展到自定义 AI；脱战返回等系统流程另按对应调用处理。
- 无动画翻页技能在英雄被心控或发生自主行动时，若 AI 实际调用了该类技能，会导致回合永久卡死；不能省略“AI 实际调用”这一条件。针对心控，可将迂回中的切换模式代码改写为调用虚拟道具执行，以规避该卡死；代价是出现一次 item 越界黑屏，原表记载该次黑屏没有其他副作用。黑屏说明仅限此流程，不推广任意 item 黑屏；该方案不适用于自主行动。证据：迂回表第38条 P944/X1102–P946/X1104，当前用户于2026-11-03确认；非本轮新增实机测试。
- 被心控英雄不计入敌方 rank；心控怪物需要结合增援与 rank 逻辑检查，否则可能造成 rank 溢出和存档死循环。
- 农场无尽任务非 Boss 房间配置具有心控能力的怪物时，被心控英雄不计为敌方怪物、不会占用敌方 rank；农场进度条增援仍会执行，不受常规阻止拖延增援的代码控制。在迂回表第36条所述心控与进度条增援叠加场景中，必定触发 rank 溢出，最终导致存档卡死、无法正常继续。因此不要在这类非 Boss 房间配置心控，不能以普通防增援配置保证安全。 卡死后的恢复方式尚不能确定：当前用户补充还存在强制回城启动项，因此不应写成必须使用存档修改器，也不能把“存档卡死”解释为任何方式均无法恢复的永久损坏。本条未核验该启动项的具体名称、参数、适用条件或恢复效果，不补造恢复命令。 证据：迂回表第36条 P914/X1070–P915/X1071；当前用户于2026-11-03明确要求按原表保留“必定卡死”，并补充恢复方式边界；非本轮新增实机测试。
# 常见错误
- 将 `.control 2` 当作持续两个个人小回合。
- 对怪物使用 `.control` 并期待产生心控。
- 允许具有心控能力的怪物在未检查增援逻辑的情况下参与可能溢出 rank 的战斗。
