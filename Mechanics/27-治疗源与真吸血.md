## 愈合早于流血腐蚀结算与1点治疗保命
知识库编写者于2026-10-26明确确认：愈合的结算早于流血、腐蚀；只要该次愈合实际恢复至少1点生命，英雄就不会死于随后这次流血、腐蚀结算。这里指实际恢复量，不是仅有愈合图标或配置值；不代表不会再次进入死亡之门，不表示免疫其他伤害，也不保证愈合失效、实际治疗为0或后续其他时点仍不死亡。不扩展到燃烧、怪物或其他未经本次确认的调用链。证据为知识库编写者确认，不冒称反编译结论，也未新增实测过程。

愈合、流血／腐蚀之后，怪癖自然进化先于 `before_turn` Buff 扣减；完整的这组相对顺序及最后1回合进化修正的用途见[Buff持续时间类型与实际清除](17-Buff持续时间类型与实际清除.md)。

## 治疗源的作用
`.source_heal_type` 声明当前 Effect 治疗所属的来源。Buff 的 `hp_heal_amount`、`hp_heal_percent`、`hp_heal_received_percent` 可通过同名 `stat_sub_type` 只修正对应治疗源。

治疗源提供基础治疗暴击率；普通攻击暴击属性不改变它，新版专用heal_crit_chance_add/multiply可修改施术者治疗暴击率。未列出暴击率的来源，当前资料只确认分类用途，不补造暴击率。

## 治疗向上取整与零治疗边界

知识库编写者确认（2026-11-02）：治疗无条件向上取整；正的不足1点治疗也会取为1点。在不考虑固定值治疗量增减益、基础治疗为正的情况下，必须将最终百分比治疗量修正压到 -100% 或以下，才能使治疗值为0；-99%等仍保留正治疗量的修正不能靠小数被舍去而封锁治疗。固定值治疗量加减须另算，不能把本结论当作禁止所有治疗；百分比修正先于固定值加减的既有结论不变。

例如，基础治疗10点、最终百分比修正为-99%时，正的0.1点仍向上取整为1点；最终修正为-100%时为0点。以上示例均不计固定值治疗量增减益。

## 生命治疗百分比加算与全局限幅

常规生命治疗的 `hp_heal_percent`（施加量）与 `hp_heal_received_percent`（所受量）先加算，再对最终百分比系数限幅；原版百分比阶段系数为 `clamp(1 + 施加量修正 + 所受量修正, 0, 2)`，即 0%～200%。这里仅表达百分比阶段，不把后置的 `hp_heal_amount` 算入该上限，也不代替暴击、取整等其他已知阶段。

生命治疗上限关联全局规则 `heal_buff_percent_max`（原版 2.0）；下限在全局规则资料中以 `heal_buff_percent_min`（0.0）记录，但当前用户于2026-11-03明确纠正：**治疗下限固定为0、不可变**。不能因规则表列出该键便推断能通过修改它得到负治疗或提高最低治疗系数。

压力伤害对应另一组全局规则：`stress_dmg_buff_min`（原版0.2）与隐藏的 `stress_dmg_buff_max`（原版3.0），同样约束其两端加算后的压力 Buff 乘区，另须按[压力伤害计算与精准加压](52-压力伤害计算与精准加压.md)考虑亮度、取整和对象边界。这组关联不适用于压力治疗；四项全局规则及证据边界集中见[极小乘极大数值迂回](54-极小乘极大数值迂回.md)的全局规则表。

依据：迂回表第54条 P1144–P1158/X1335–X1355，以及全局规则整理第29、30、147、148行；当前用户于2026-11-03确认两端加算与限幅，并补充治疗下限不可变。本轮没有新增实机测试。不据此保证未经核对的特殊治疗调用；后置固定治疗仍能突破百分比抑制，不应写成彻底禁疗。

## 治疗量的先百分比后固定值

治疗量与 `combat_stat_*` 系战斗属性 Buff 的“先加后乘”正好相反：

1. 先结算治疗造成量、治疗所受量等百分比修正；
2. 再结算 `hp_heal_amount` 等固定治疗量加减。

因此，固定治疗量不会被此前的百分比治疗修正再次相乘。即使治疗造成量或治疗所受量被压制到 `-999999%`，只要最终还有 `+1` 固定治疗量，该固定值仍可突破百分比治疗限制并产生 1 点治疗。不要用极端负百分比治疗量来代替“禁止一切治疗”，因为它无法封锁后置的固定治疗量。

### 固定治疗的禁疗选点

新版新增 `hp_heal_amount_received` 固定值受疗修正；此前“没有固定受疗”限制已退休。不能仅靠百分比禁疗推定所有固定治疗消失，新字段与其他固定修正的完整内部顺序未提供。

历史证据：迂回表第24条 P589/X661；其无固定受疗字段的时代边界已由新版新增字段替代，其他治疗来源结论仍按对应条件使用。

可将结算顺序概括为：

```text
最终治疗量 = 百分比修正阶段的治疗结果 + 固定治疗量修正
```

这里强调的是结算先后及固定治疗可以突破百分比抑制；不能把 `combat_stat_*` 的“基础值先加固定值、再乘百分比”公式套用于治疗。

## 同一 Effect 行内减压与固定值治疗的顺序

迂回表第114条记录：当同一条 Effect 定义行同时写压力治疗 `.healstress` 与固定值生命治疗 `.heal` 时，应先写 `.healstress`、再写 `.heal`；若先写 `.heal`、后写 `.healstress`，原表观察为固定值 `.heal` 不生效。将固定值治疗换成百分比治疗 `.heal_percent` 后，这项先后要求不适用，`.heal_percent` 可写在 `.healstress` 前或后。

本条只覆盖同一 Effect 定义行内这三种字段的该项顺序观察，不把它推广到不同 Effect 定义之间、Effect 分行、queue/AWR 时序或其他治疗/减压字段。证据：迂回表第114条 P1801/X2296、P1803/X2299、P1804/X2300、P1805/X2301、P1807/X2304；当前用户于2026-11-04确认知识库未收录一般边界并要求补入。本轮未新增游戏测试。

## `.can_crit_heal`
- `.can_crit_heal true`：允许同一逻辑 Effect 中的 `.heal` 或 `.heal_percent` 按治疗源进行治疗暴击。
- `.can_crit_heal false`：禁止同一逻辑 Effect 中的 `.heal` 和 `.heal_percent` 暴击。
- 同一逻辑 Effect 包括同一 Header 内换行，以及同名 `.name` 分行；跨 Mod 的同名 Effect 文件仍参与叠加，不能假定定义因文件同名而失效。
- 本字段不负责改变治疗暴击率，只控制当前治疗是否允许暴击。

## 治疗暴击附加效果：`crit_heal_stress_heal`

原版 `DarkestDungeon\effects\base.effects.darkest:2067` 定义了 `crit_heal_stress_heal`：`.target "target"`、`.chance 100%`、`.healstress 4`、`.on_hit true`、`.on_miss false`、`.queue true`。原版配置中没有其他代码引用该 Effect；迂回表第93条 P1475–P1477/X1800–X1802 记载它由红钩内建治疗暴击机制调用，在治疗暴击时令受治疗目标减压4点。此处的内建调用行为来自迂回表记载，原版文件本身确认的是该 Effect 定义及参数。

保持同一 `.name` 并采用 Effect 分行，可以在这项治疗暴击触发上追加其他结果。迂回表举例令该 Effect 带出 Buff，再用 Buff Rule 与 `remove_if_not_active: true` 限定效果：目标具有指定怪癖、场上存在指定怪物，或目标背包中有指定饰品／道具时才保留相应 Buff。因为这是全局触发接口，扩充分行会影响所有英雄；条件示例是原表方案，不代表每种 Rule、物品目标及调用场景都已逐一实测，也不保证完全没有其他影响。来源：P1478–P1483/X1804–X1810。

分行时不要在 Effect 行分别声明不一致的 `duration` 或 `buff_duration_type`；原表记录同名分行共享这类参数，重复且不一致时只有一个值实际生效，可能使 Buff 持续时间偏离预期。该迂回应把持续时间及其类型写在 Buff 定义中。P1484–P1485/X1812–X1814 的边界只针对该分行用法。

参数应以原版定义为准：P1474/X1798 的游戏源行是 `.on_hit true .on_miss false`；P1487/X1817 的示例把 `.on_miss` 写成 `true`，与原版 `base.effects.darkest:2067` 不同。按当前用户2026-11-04指示，记录游戏源文件的原样定义，不将P1487的不同取值当成可覆盖字段或另一个已验证版本。其余字段也应保留原版行的既有值；追加参数以 `.buff_ids` 为主，并按同名 Effect 分行规则核对参数合并。使用该接口时应考虑其全局兼容性，见P1486–P1489/X1816–X1820。本补录依据原版定义和迂回表记录，未新增实机测试。

## 真吸血
技能使用：

```darkest
.damage_heal_base_class_ids <base_class_id>
```

启用真吸血。其基础回复量为最终直伤的 `100%`：

- 以最终伤害跳字为依据，伤害跳字多少，就按多少生命计算基础回复。
- 计算过量伤害。
- 只计算技能直伤，不计算技能附带的 `.health_damage` 等真伤。
- 对尸体造成的直伤也能触发真吸血。
- 最终伤害被格挡或降为 `0` 时，没有可供回复的伤害量。
- 参数列出多个 base class ID 时，多个符合 ID 的单位同时获得回复。
- AOE 是否把所有目标的最终直伤合并后计算治疗，目前尚未确认；不要让精确机制依赖该边界。

迂回表第88条 P1422/X1715 经当前用户于2026-11-04确认并限定：相同真吸血代码重复分行会导致翻倍吸血。避免重复是对**每个技能等级最终合并后的定义**而言；各等级分别填写一次不构成跨等级重复。若采用正确的无等级共用分行，共用部分整体写一次即可，不要再在各等级重复写同一内容；仍须遵守[技能分行](37-技能同ID分行与无等级共用分行.md)的等级与目标规则。本轮未新增实机测试。

真吸血最终倍率不是简单由单个 Buff 决定。以 `hp_heal_percent/damage_heal = -0.95` 为例，它不保证最终一定只留下 `5%`：还要与未限定治疗源的治疗/受疗修正，以及其他限定为 `damage_heal` 的治疗量和受疗量修正共同加减计算。
