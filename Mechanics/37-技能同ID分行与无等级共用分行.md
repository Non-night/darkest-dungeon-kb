## 适用边界：不是所有 Header 都支持同 ID 分行合并

本专题的技能同ID分行规则不适用于模式定义 `mode:`，也不能仅因Effect支持同名分行就将其规则推广到模式。

知识库编写者提供Cathelia2026-11-08 22:52的测试并确认：同一文件相邻两条 `mode: .id foreigner .is_raid_default true` 分别列2个和6个 `.battle_start_effect_ids`，模式名称重复显示；战斗开始只执行上方第一条的2个Effect，第二条6个未执行，不是合并执行8个。聊天中的“高者生效”应理解为**文件内书写位置靠上**，不得误写成Mod优先级高者生效。

因此不要用重复同ID的 `mode:` 追加战斗开始Effect。本例不确定跨文件、跨Mod/DLC或其他模式字段重复定义的行为，也不影响已确认的技能/Effect分行规则。原始定义、截图和证据分层见 `Sources/mode_split_20261108.json`；字段说明见 `Info/headers/Info.mode.md`。本轮Agent未运行游戏测试。

## 定义
在英雄 `combat_skill:` 中，可以用多个 Header 重复定义同一个 `.id`。其中：

- 带 `.level N` 的 Header 是该技能对应等级的定义；
- 不写 `.level`、但与各等级使用同一 `.id` 的 Header，可作为所有等级共用的分行；
- 本文把这种不写等级、向全部已有等级补充共同内容的写法称为**无等级共用分行**。

它适合把所有等级完全相同的字段抽离出来，减少重复文本并提高可读性。它不是另一项独立技能。

## 共用分行的位置要求

知识库编写者于2026-11-08补充：同一技能的无等级共用分行若写在所有带 `.level` 的等级行之前，其中的 `.effect` 必定不会发生；整条共用行疑似被视为没写，但其他字段是否同样失效尚未确认，不能将该推测写成已确认的全部字段行为。

创作时应先写完该技能所有带 `.level` 的等级行，再在它们下方书写同 ID 的无等级共用分行。不能将共用行前置并指望后续等级行继承其 `.effect`。本条不确定共用行夹在等级行之间时的行为，也不撤销每个等级首行必须提供非自身 `.target` 的独立规则。

来源：`Sources/skill_shared_line_order_20261108.json`；知识库编写者确认的表现与推测分开记录，Agent未自行执行游戏测试。

## 基本合并行为
例如：

```darkest
combat_skill: .id "example_skill" .level 0 .atk 95% .crit 5% .target 34 .effect "Example Level 0"
combat_skill: .id "example_skill" .level 1 .atk 100% .crit 6% .target 34 .effect "Example Level 1"
combat_skill: .id "example_skill" .type "ranged" .dmg -50% .launch 21 .target 34 .effect "Example Shared A"
combat_skill: .id "example_skill" .effect "Example Shared B" "Example Shared C"
```

两条无等级分行的共同内容会接入 `.level 0`、`.level 1` 等同 ID 的等级定义。多值列表字段如 `.effect` 可借此把共用引用继续追加到各等级原有列表之后；实际顺序仍取决于分行的书写顺序。

相同多参数内容重复分行不会自动去重。迂回表第88条 P1422/X1715 经当前用户于2026-11-04确认：重复真吸血代码会导致翻倍吸血，须按**每个技能等级最终合并后的定义**避免重复；不是所有等级加起来只能写一次。逐等级分别写一次可以；正确采用无等级共用分行时，共用部分整体写一次，不要再在各等级重复相同真吸血内容。单参数字段仍按后写覆盖处理。本轮未新增实机测试。

## `valid_modes` 的无等级共用写法

`valid_modes` 也属于可以放入无等级共用分行的技能字段。如果同一个技能的所有等级都允许完全相同的模式集合，不要在每个 `.level` 行重复写一份；应先写完各等级定义，再在技能最后追加不写 `.level` 的同 ID 分行：

```darkest
skill: .id "example" .level 0 .effect "level_0"
skill: .id "example" .level 1 .effect "level_1"
skill: .id "example" .level 2 .effect "level_2"
skill: .id "example" .valid_modes "mode_a mode_b"
```

只有当模式集合本身随等级变化时，才在各等级行分别填写 `valid_modes`：例如低等级允许 `mode_a`，高等级改为 `mode_b`。单行 `valid_modes` 的已知模式数量上限仍按专题 75 处理；超过上限时继续按无等级共用分行拆分，但必须复核同 ID 分行的实际合并顺序，不要把等级差分和共用追加混在一起。





该技能先写 0 至 4 级各自的 `.atk`、`.crit`、`.target` 与等级专用 `.effect`，随后用三条不写 `.level` 的同 ID `combat_skill:` 分行追加共用的类型、伤害修正、位移、启动站位、目标站位、真吸血职业与 Effect 列表。

## 单参数字段的覆盖顺序
对于同类单参数字段，后写的有效值覆盖先写的值。因此：

1. 等级行先提供该等级的字段；
2. 下方的无等级共用分行再次提供同一单参数字段；
3. 无等级分行中的值覆盖各等级此前的值。

所以无等级共用分行应放在需要被它补充或覆盖的等级行之后。不要把“分行合并”误解为所有重复字段都会同时保留；单参数字段与列表字段必须分别判断。

## `.target` 的特殊规则
`.target` 不能完全套用普通单参数字段的直觉：

- 技能目标不为自身时，必须在同一技能**每个等级的第一条带 `.level` 的定义**中填写参数非空的 `.target`。同等级可以有多条定义；不是每条带等级的分行都要重复写目标。
- 第一条等级定义未写有效 `.target` 时，即使同等级第二条分行及无等级共用行都写了目标，仍视为未写，技能只对自身释放。不能靠后续分行补救。
- 除每个等级第一条定义之外，其余分行均无须重复填写 `.target`。若每个等级第一条定义已有有效 `.target`，写在所有等级行下方的无等级共用行可以用有效 `.target` 覆盖各等级原有目标站位。
- `.target` 后参数为空等同于没有填写，不能作为有效的等级行占位。
- 英雄 `combat_skill:` 最终没有有效 `.target` 时，不是“目标未定义后报错”，而是被识别为指向英雄自身的友方技能。
- 不要把某个等级第一条定义中填写的 `.target` 当作其他等级的首行目标；需要非自身目标的每个等级都应遵守首行要求。

这意味着：即使所有等级目标完全相同，也不能为了进一步省略文本而只把 `.target` 写在无等级共用分行；否则各等级可能因最终没有有效 `.target` 而变成指向自身的友方技能。



## 相同 Effect 的复用
- 如果同一技能的不同等级需要一模一样的效果，并且 Effect 的字段、数值、目标、条件、时序与生效次数要求均相同，不建议按等级创建多份内容相同的 Effect 定义。
- 应只创建一个目标 Mod 自有的 Effect ID，并在每个等级重复引用该 ID。这里复用的是当前 Mod 的自定义 Effect，不是优先复用原版或其他 Mod 的同名定义。
- 如果所有等级对该 Effect 的引用位置与相对顺序都相同，并且无等级分行追加后不会改变预期触发顺序或时序，可把引用抽到无等级共用分行。
- 如果该 Effect 必须位于等级专用 Effect 列表中的特定位置，或不同等级的相对顺序不同，则应在各等级行分别引用同一个 ID；不要为了抽取共用分行而改变 `.effect` 的书写顺序。

```darkest
combat_skill: .id "example_skill" .level 0 .atk 95%  .effect "mod_shared_effect"
combat_skill: .id "example_skill" .level 1 .atk 100% .effect "mod_shared_effect"
combat_skill: .id "example_skill" .level 2 .atk 105% .effect "mod_shared_effect"
```

当引用顺序允许统一追加时，可改为：

```darkest
combat_skill: .id "example_skill" .level 0 .atk 95%  .target 34
combat_skill: .id "example_skill" .level 1 .atk 100% .target 34
combat_skill: .id "example_skill" .level 2 .atk 105% .target 34
combat_skill: .id "example_skill" .effect "mod_shared_effect"
```

## 使用建议
- 只把所有等级确实相同的内容放进无等级共用分行；等级成长数值仍留在各自 `.level` 行。
- 同一技能可以使用多条无等级分行，以拆分较长的 `.effect` 列表或按功能组织字段。
- 完全相同且调用环境相似的效果应复用一个自定义 Effect 定义；能否进一步把引用抽入无等级分行，则取决于引用顺序和时序是否保持不变。
- 需要依赖覆盖时，必须检查 Header 的实际先后顺序。
- `.target` 必须遵守上述特殊规则，不能按普通共用字段处理。
- 分行用于减少重复和改善阅读，不代表应该为了压缩文本而隐藏关键等级差异。

## Agent 实现检查
1. 是否以相同 `.id` 识别等级行与无等级共用分行，而没有把后者误判成独立技能？
2. 所有等级相同的字段是否可以安全抽到无等级行？
3. 多个相似调用位置需要的 Effect 若完全相同，是否只创建了一个目标 Mod 自有的 Effect 定义并重复引用，而没有按等级复制多份相同定义？
4. 若所有等级引用同一个 Effect，是否确认无等级共用分行不会改变该引用与等级专用 Effect 的相对顺序、触发时序或生效次数？不能安全抽取时，是否在各等级行分别引用同一个 ID？
5. 对重复单参数字段，是否按后写覆盖先写处理？
6. 对 `.effect` 等多值列表字段，是否保留等级专用引用并按分行顺序追加共用引用？
7. 非自身技能是否在每个等级的第一条定义显式写了非空 `.target`，没有尝试靠同等级后续行或无等级分行补救？其余分行不必重复写目标。
8. 若无等级 `.target` 用于统一覆盖，是否位于所有等级行下方？
9. 是否按每个等级分别核对首行目标，而没有误用其他等级的首行目标？
10. 如果所有等级的 `valid_modes` 完全相同，是否已经抽到技能最后的无等级共用分行；只有模式集合随等级变化时，才按等级分别书写？
