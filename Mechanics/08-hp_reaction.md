## 本次调用的目标上下文

## 阈值
- `.hp_ratio <x> .is_under true`：当前生命比例小于等于 `x` 时满足。
- `.hp_ratio <x> .is_under false`：当前生命比例大于等于 `x` 时满足。
- 阈值是闭区间，等于阈值时也会触发。
- `.is_under true` 表示生命值向下变化（损血方向），`.is_under false` 表示生命值向上变化（回血方向）；若使用取反规则，边界变为开区间。不要把方向字段误解为“当前生命低于/高于阈值”的静态比较。

## 触发与插入时机
- 知识库编写者2026-10-31明确：普通伤害和真伤即使足以致死，仍会触发满足条件的生命反馈（`hp_reaction`）；不能通过伤害致死来避免生命反馈内容发生。具体触发项仍按实际生命变化、阈值、方向及Info书写顺序判断。本条为知识库编写者确认，非本轮新增实机测试；不外推到 `.kill`、`kill_enemy_types` 或最大生命变化等其他机制，也不据此补造死亡结算与所有Effect的完整时序。
- 当前用户于 2026-10-03 补充：单位只要拥有向上生命反馈（`.is_under false`），受到任何治疗时都会进行对应的向上 `hp_reaction` 检查；若该次治疗后的状态满足阈值、方向及书写顺序条件，就会立即触发并插入相应 Effect。不要把检查范围误缩成某一种治疗源或只限于 size-0。
- 生命反馈会在生命值发生变化时立即检查，并在条件满足时立即执行；一次治疗如满足多个候选阈值，仍按 Info 中向上 reaction 的书写顺序选择第一条匹配项，详见“多阈值”。
- 它可以插入当前 `spawn: .effects` 序列的中间；生命反馈所带出的 Effect 结算完毕后，再继续原 spawn 序列。
- spawn Effect 本身也可以插入召唤者技能 Effect 的中间。
- `hp_reaction` 写在哪个单位的 Info 中，该单位就是其引用 Effect 的施术者。

## 多阈值
- 一次独立的生命值变动跨越多个 `.hp_reaction` 阈值时，按 Info 中这些生命反馈代码的自上而下书写顺序检查；只触发第一条同时满足本次跨越范围和方向条件的 reaction。
- 第一条代码不要求是最大或最小阈值；无论它位于阈值序列的最高、最低还是中间位置，只要它是代码中最先满足条件的条目，就优先于后面的条目。
- 不能按生命值距离最近、阈值数值最高或阈值数值最低来推断同一次生命变动选择哪条 reaction。
- 这里的“一次只触发一条”只针对一次独立的生命值变动，不是针对整段技能或整段 Effect 序列。
- 多个 Effect 造成的多段真伤，即使属于同一个 `queue` 时序，也分别构成独立的生命值变动；每一段只要成功跨越至少一个符合方向的阈值，就可以分别触发一次 `hp_reaction`。
- 最大生命值 Buff 造成的最大生命值／当前生命比例变化本身不视为普通生命值变动，不触发 `hp_reaction`；英雄因最大生命值下降而同步降低当前生命时也不能据此套用普通损血反馈。

## 零血不死怪物与负生命阈值

当前用户于 2026-10-04 补充：零血不死的怪物并不是把生命锁在 0；其生命可以到达负数，单位仍不死亡，并且还可以继续受到向下生命变化。因而，对这类怪物而言，负数生命比例阈值的 `.hp_reaction` 具有实际意义，不能因为“生命到 0 仍不死”就把负阈值判为无效或不可达。

设计或审查零血不死怪物的生命反馈时，必须按实际生命值、最大生命值、负数生命比例、取整和继续向下扣血后的落点计算；仍需区分死亡门、死而不僵、零血不死和普通生命反馈，不能把它们当成同一状态。负阈值是否能被某个具体伤害量跨越，仍按该单位的实际生命变化与 reaction 书写顺序逐条核对。

## 生命反馈的理论可达性检查

当前用户补充（2026-09-25）：使用生命反馈 size-0 时，必须先检查其血量变化在理论计算上能否到达预期的 `hp_reaction` 阈值；这里的理论检查不考虑外部环境干扰，但必须按实际初始生命、最大生命、治疗/伤害数值、百分比与固定量修正、取整、生命方向和其他已写入的同层数值计算。不能只因为某条 reaction 的阈值写法正确，就假定实际生命变化一定能进入该阈值区间。

理论落点若无法进入目标阈值，或会直接越过预期分支、进入更高/更低的其他分支，就必须调整 size-0 数值流程、阈值或中间生命变化；完成这项理论可达性核对后，才继续考虑最大生命修正、抗性、外部 Buff、重启误触发等干扰。该检查与“中点落点”互补：先确认目标区间可达，再把可达落点放在目标阈值与相邻阈值之间的安全位置。

## 生命反馈阈值的中点落点

知识库编写者补充（2026-09-20）：size-0 用真伤或治疗把生命比例送入某个 `hp_reaction` 分支时，不要把生命量刚好停在触发阈值上。应把预计落点放在“目标阈值”和相邻下一个阈值之间的中点，以给最大生命修正、取整、治疗/真伤计算误差和其他干扰留下更大余量。

### 向下损血

将向下阈值按从高到低记为 `T1 > T2 > ...`：

- 要触发 `T1`、又避免直接落入更低的 `T2`，预计落点取 `(T1 + T2) / 2`；
- 如果没有更低阈值，则把下界视为 0，预计落点取 `T1 / 2`。

例如：

- 只有 `.hp_ratio 0.25 .is_under true` 时，真伤预计把生命从满血降到 `0.125`（12.5%），而不是刚好降到 25%；
- 同时还有 `.hp_ratio 0.125 .is_under true` 时，针对 25% 分支预计落点为 `(0.25 + 0.125) / 2 = 0.1875`（18.75%），这样仍高于 12.5% 分支的阈值。

### 向上治疗

向上阈值按从低到高记为 `T1 < T2 < ...`：要触发某个阈值、又避免直接跨入更高阈值时，预计落点取该阈值与下一个更高阈值的中点；如果没有更高阈值，则把上界视为满血 1，取 `(T1 + 1) / 2`。这是一条落点设计原则，不是把 Effect 的治疗公式改成固定中点；实际仍要结合整数生命、最大生命、治疗/真伤取整和其他 Buff 复核。

该中点策略与 sentinel 互补：sentinel 负责重启误触发时先命中无影响分支，中点落点负责正常生命反馈时尽量远离相邻真实阈值。不能因为阈值是闭区间，就把“刚好等于阈值”当作安全落点。

## 重启误触发
游戏重启后，若单位当前生命比例已经位于某条 reaction 的满足区间，即使没有发生跨越阈值的生命变化，也可能错误触发该 reaction。使用长期留场或可被存档的中间单位时，应提供前置无意义 reaction 或其他保护，不要让首条有效 reaction 直接承担关键效果。

### size0Spawner 的方向 sentinel

当前用户本次补充要求，所有使用生命反馈的 size-0 都要把重启保护落实到具体 `hp_reaction` 行，而不是只在说明中提醒：

```text
// 向下生命反馈存在时，先于所有真实向下 reaction
hp_reaction: .hp_ratio 0.99 .is_under true .effects SZ0SPAWNER_NOOP_DOWN

// 向上生命反馈存在时，先于所有真实向上 reaction
hp_reaction: .hp_ratio 0.01 .is_under false .effects SZ0SPAWNER_NOOP_UP

// 此后才写会产生实际效果的 hp_reaction
```

`.99` 与 `.01` 不是任意装饰数值：它们把重启时可能落入真实反应区间的 size-0 先导向无影响 Effect。`0.999`、`0.9999` 等同方向的更高保护阈值可以作为同类设计，但必须保持 sentinel 位于真实 reaction 之前，并按当前 size-0 的实际生命比例复核。无影响 Effect 可采用无效 Effect、无关 Buff 或已知 `.tag 0` 占位；`.tag 0` 不施加标记但可能产生红字，不能描述成完全无副作用。

## 与 size-0
知识库编写者于2026-09-19补充：size-0 A 在自己的 spawn 中 set 成 B 后，虽然 A 的 spawn 剩余列表继续执行，但变身完成后的生命反馈只使用 B 自身的 hp_reaction；不启动 B 的 spawn。反馈仍需满足阈值与方向，set 本身重置/继承生命时的反馈触发细节未确认。详见[连续 set 执行链](28-spawn、生命反馈与size0执行链.md)。

死亡门不只检查 spawn 列表：若 `hp_reaction` 带出的召唤或对自身的 set 的最终目标处于已经死亡、死而不僵状态，这两个操作通常会被阻断；对应 Effect 同时显式写 `.can_apply_on_death true .can_apply_on_corpse true` 时例外。普通生命反馈的其他 Effect 是否继续执行，不能被概括成召唤/set 也能成功；需要的操作必须在目标进入死而不僵前完成。

利用最大生命、治疗、极小伤害和多个闭区间阈值，可以把条件结果编码为 size-0 的生命比例，形成生命反馈二段式。完整流程与最高难度生命修正处理见：[spawn、生命反馈与 size-0 执行链](28-spawn、生命反馈与size0执行链.md)。
