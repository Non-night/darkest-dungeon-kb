## 攻击选定目标时的预计算
攻击技能选定目标时，精准/闪避、伤害/防御、暴击/被暴击等主要面板计算已经完成。因此，即使 AWR 发生在直伤跳字前，AWR 中临时施加普通攻击、伤害或暴击 Buff，通常也不能回头修改本次攻击已经完成的对应面板计算。

## 暴击率与所受暴击率
- 目标的 `crit_received_chance` 会加入攻击者针对该目标的最终暴击率计算。正值提高该目标被暴击的概率，负值降低该概率。
- 攻击者自身暴击率修正、目标所受暴击率修正及其他相关项相互加算；所有修正汇总后，最终实际暴击概率才截断在 `0%` 至 `100%`。
- 截断前的超量数值仍可抵消反向修正。例如合计达到 `110%` 后再承受 `-10%`，最终为 `100%`；不能先把 `110%` 截为 `100%` 再计算成 `90%`。
- 反击是特殊的攻击技能，其伤害、暴击等常规战斗数值按攻击技能结算，因此目标的 `crit_received_chance` 会参与反击暴击判定。
- 这不表示反击在所有系统里都等同普通攻击技能。普通攻击技能的 AWR 分层、攻击／近战／远程／暴击饰品 Trigger 等机制仍有反击专属例外，必须分别查阅对应规则。

## 直伤公式
当前整理的直伤公式为：

```text
[
  面板伤害 × (1 + 技能伤害修正)
  + (若 技能伤害修正 != -100% 或 技能为反击，则计入固定值伤害 Buff；否则为 0)
]
× (1 + 百分比伤害 Buff)
× (1 + 目标易伤 Buff)
```

等价条件：

- 技能伤害修正不是 `-100%`：计入固定值伤害 Buff。
- 技能是反击：即使伤害修正为 `-100%`，仍计入固定值伤害 Buff。
- 非反击技能且伤害修正恰为 `-100%`：不计入固定值伤害 Buff。

### `-100%` 技能伤害修正与反击、跳字、受击反馈

迂回表第116条所引 KKU/TPN 测试还区分了以下调用结果：

- **常规技能自身为 `-100%`**：原表观察为不会触发目标的反击，也不会显示 `0` 伤害数字。它与用 Buff 把本来会显示伤害的攻击倒扣到实际 `0` 不等效；不要把两者当作同一反击判定路径。
- **怪物伤害参数 `.dmg 0 0`**：原表观察为等效于英雄侧技能 `-100%` 伤害修正，不触发反击。
- **英雄基础武器伤害 `.dmg 0 0`**：原表观察为所有技能等效于 `-100%` 伤害修正；固定值伤害提升 Buff 不计入，即使面板显示提升，攻击时仍没有伤害数字且不触发反击。
- **反击技能自身为 `-100%`**：与常规技能不同，原表观察为反击命中时仍显示 `0` 伤害数字；符合前述公式，反击的固定值伤害 Buff 仍计入，且固定值伤害提升可使其打出实际伤害。
- 常规技能的 `-100%` 伤害修正**不阻止目标的受击反馈**；原表明确区分目标反击与饰品三种 `was_hit` Trigger、英雄/怪物 `skill_reaction: .was_hit_performer_effects`，后者仍会触发。

这些是原表所引测试的历史观察，范围限于上述常规技能、反击技能、武器基础伤害和目标受击反馈路径；不扩展到其他伤害来源、其他命中 Trigger 或任意得到实际 `0` 伤害的流程。证据：迂回表第116条 P1822–P1835/X2326–X2345；当前用户于2026-11-05确认按所列边界补入。本轮未新增游戏测试。

“目标易伤 Buff”指目标身上的 `damage_received_percent`，也称硬减伤/易伤乘区。它是最后的独立乘区。

## 防御、Buff 穿甲与技能绝对穿甲

`ignore_protection` Buff 提供的是与目标防御等量相抵的穿甲值，不是“按目标现有防御再乘一个忽略比例”。多个 `ignore_protection` Buff 彼此加算。

基本关系可按以下实例理解：

- 目标有 `50%` 防御，攻击者合计有 `30%` Buff 穿甲：本次伤害等效于面对 `20%` 防御。
- Buff 穿甲高于目标防御：最终按 `0%` 防御处理，超出的正穿甲没有额外收益，也不会把防御降成负值来增伤。
- 负数穿甲等效于提高目标对该攻击者生效的防御。例如目标原有 `80%` 防御，攻击者为 `-20%` 穿甲时，等效于面对 `100%` 防御。

按迂回表第26条 P619/X695、P622/X698、P634/X712 的历史结论，目标防御高于80%时，Buff 穿甲只需抵消面板封顶的80%，超出部分不参与抵消；防御来自 Buff 或怪物 Info 天生参数时均按此处理。例如合计防御120%、攻击者40%穿甲，按80%−40%=40%防御结算。例子为依据原表的算术推导，不是本轮实测。当前用户于2026-11-02询问后指定此段以迂回表为准，同时明确不确定当前版本是否仍如此；因此撤回“120%−40%仍按80%”的相反记忆作为采用依据，但保留当前版本适用性未确认的边界，不能宣称已在当前版本复测成立。

技能参数中的“无视防御”与 Buff 穿甲不是同一种机制：它属于**绝对穿甲**。技能声明绝对无视防御后，无论攻击者身上有多少正数或负数穿甲 Buff、目标身上有多少防御，最终都按目标 `0%` 防御结算。不得用极大的 `ignore_protection` Buff 冒充技能绝对穿甲，也不得把绝对穿甲理解为普通穿甲数值与防御相减。

## 技能“伤害修正”与 Buff 伤害必须严格区分
技能自身的“伤害修正”和 Buff 提供的伤害完全不是同一个概念，也不能互相替换：

- **技能伤害修正**：属于当前技能自身的伤害参数，直接参与 `面板伤害 × (1 + 技能伤害修正)`。例如设计稿写某技能“伤害修正 `-50%`”，指的是该技能自身的修正，不是给角色施加一个 `-50%` 伤害 Buff。
- **固定值伤害 Buff**：位于技能伤害修正之后的加法区，并受到“非反击技能且技能伤害修正恰为 `-100%` 时不计入”的特殊条件限制。
- **百分比伤害 Buff**：位于下一独立乘区，即公式中的 `× (1 + 百分比伤害 Buff)`。
- **目标易伤 Buff**：位于最后的目标乘区。

因此，即使两个数值表面上都写成 `+20%` 或 `-50%`，只要一个是技能伤害修正、另一个来自 Buff，它们在公式中的位置、可被干涉的时机和特殊边界都不同。Agent 解析设计稿时必须保留原术语；不得把“技能伤害修正”擅自实现成伤害 Buff，也不得把 Buff 增伤回填成技能伤害修正。

## AWR 易伤可以干涉本次直伤
目标易伤乘区在 AWR 之后才参与本次直伤计算，因此它是已知例外：

- AWR 中给攻击目标施加 `damage_received_percent`，可以修改本次即将出现的直伤跳字。
- 普通施术者伤害 Buff、精准 Buff、暴击 Buff 在 AWR 才施加时通常已经来不及修改本次预计算。

## AWR 对受击目标属性的已知边界

迂回表第106条 P1636–P1645/X2050–X2061 进一步记录了 apply_with_result true queue false 对敌方受击目标的有限干预范围：

- 对受击目标施加 damage_received_percent 易伤，可以改变当次直伤伤害量；
- 对受击目标施加反击三要素的负向遏制，可以改变当次直伤是否触发反击；
- 对受击目标施加反伤相关 Buff 的负向遏制，可以改变当次直伤是否触发反伤；
- 对受击目标施加易爆，不能改变当次直伤的暴击率；
- 对受击目标施加闪避，不能改变当次直伤的命中率；
- 这些边界针对攻击者修正目标一侧的 Effect；用 AWR 修正攻击者自身不能干预该次直伤，需按原表提示另查 skill_instant 等路径。

因此，AWR 不是任意属性都能回溯修改本次攻击的通用提前层。除上述已记录的易伤、反击遏制和反伤遏制外，其他属性是否能在该窗口改变本次直伤仍须分别核对。P1646–P1649/X2063–X2066 记录的用途包括按敌方数量实时改变当次伤害，以及用通用饰品实现无视反击、无视反伤；这些用途依赖上述已确认的属性边界，不扩展为所有攻击属性或所有调用方。本补录依据第106条及当前用户2026-11-04确认，未新增实机测试。

迂回表第136条进一步记录：AWR 召唤经 spawn 继承时序而干预本次直伤的实测声明，特指对目标施加 `damage_received_percent` 易伤；不能把“召唤物的 spawn 处于 AWR”理解为任意 Buff 或属性都能影响本次直伤。受击侧 `hp_reaction` 与饰品受击 Trigger 的失败边界另按第136条记录，P2088–P2089 的时序原因仍属原表推测。

### 临时易伤的默认清理时序

如果易伤的设计目的只是干涉**本次直伤**，通常推荐在本次直伤之后紧接着进入的技能 `queue false` 时序中清除，而不是让它继续保留到 `queue true`、ActorDot 或后续行动：

1. AWR：向当前攻击目标施加临时 `damage_received_percent`；
2. 本次直伤：读取该易伤乘区；
3. 技能 `queue false`：按明确 Buff ID 清除临时易伤。

这样既能让易伤参与本次直伤，又能尽早结束其影响窗口，降低它错误干涉饰品 Trigger、附魔 Effect、后续 `queue true` Effect、ActorDot 或其他伤害的风险。这里的 `queue false` 清理是**临时易伤的常规推荐写法**，不是所有易伤 Buff 的强制规则：若设计明确要求它影响后续 Effect、持续到更晚时序或保留若干回合，则必须按照实际设计另定生命周期，不能机械清除。

清理 Effect 应精确指向持有临时易伤的设计目标，并按该临时 Buff 的明确 ID 清除；不得为了方便把清理范围扩大到设计之外的单位，也不得误清除目标身上其他来源的常规易伤。

### “本次眩晕成功则本次直伤获得易伤”
可按以下顺序设计：

1. AWR：先对目标尝试眩晕。
2. AWR：再以极高减益概率给目标施加临时易伤 Buff；该 Buff 使用 `is_actor_status stunned` 判断持有者自身已经眩晕。
3. 本次直伤：读取目标临时易伤乘区。
4. `queue false`：按明确 Buff ID 清除该临时易伤，避免影响后续伤害。

跨侧 Buff 仍要判定目标减益抗性，因此临时易伤的最终减益成功率应明显高于 `600%`；社区常用 `2000%` 以上，保守迂回可使用约 `4000%`。

不能直接用 `.keyStatus` 完成这一步：`.keyStatus` 是通常与 `.combat_stat_buff` 系列搭配的条件简写，会产生默认属于 `bsrc_instantSkill` 源的简写 Buff；这里需要把 `damage_received_percent` 精确施加到当前攻击目标身上，并只在本次直伤窗口内存在。为了规避 `.keyStatus + target` 的致命组合而改用 `target_group` 给整组单位施加易伤，同样违反目标最小化原则，不能采用。

## 眩晕概率的表述
设计中写“眩晕概率 `100%`”默认指 Effect 的基础 `.chance 100%`，仍然经过目标眩晕抗性。只有明确写“必定成功”或“无视抗性”时，才按不可抵抗或极端概率方案设计。

## 眩晕施加与恢复时的全局 Buff



- `stun_onset_buffs`：眩晕成功施加时给目标附加指定 Buff；列表当前为空，因此原版默认不通过此字段附加眩晕施加 Buff。
- `stun_onset_buff_consecutive_applies`：控制连续眩晕时，onset Buff 是否允许连续施加；当前值 `false`。当前列表为空时，这个设置没有 onset Buff 可供施加。
- `stun_recovery_buffs`：眩晕自然结束时给目标附加指定 Buff。这里的自然结束指眩晕成功令目标空过回合后随之移除，不把驱散等其他清除方式一概视为该触发。当前指定 `STUNRECOVERYBUFF`。
- `stun_recovery_buff_consecutive_applies`：控制连续眩晕自然结束时，recovery Buff 是否允许连续施加；当前为 `true`，与防止连续眩晕的设计相配。

原版 `STUNRECOVERYBUFF` 定义为 `resistance` / `stun`，`amount: 0.5`、`duration: 2`，即2回合的50%眩晕抗性 Buff。迂回表第95条 P1508/X1848 将其解释为防连晕的自动抗性。这里记录的是内建 Buff 钩子及原版默认配置，不表示任何自定义眩晕都必定成功，也不据此推导 Buff 的刷新、合并或精确叠层算法。

这些规则以 Buff ID 列表控制全局眩晕事件，不是直接填写 Effect。迂回表第95条 P1501/X1838 记载，O’Nightmare 曾用相关全局规则制作自定义眩晕机制；P1511/X1853 提醒此类改动影响全局，兼容性处理困难，通常不建议改动。将其保留为设计警告，不解释成绝对无法修改。依据全局规则整理第149–152行、对应原版 rules/buff 定义及迂回表第95条 P1501–P1511/X1838–X1853；当前用户2026-11-04要求与全局规则一并记录，未新增实机测试。

## 反击减压与 riposte Rule 的特殊边界

迂回表第109条 P1667–P1703/X2096–X2143 记录了一项反击专用的压力治疗异常：减压 Effect 无论直接写在反击技能定义中，还是由 riposte_effect 引出，都无法受到 rule_type: riposte 的压力施加量 Buff 或压力所受量 Buff 修正。原表将其作为特殊情况记录，原因未确认。

原表对照中，反击时使用 riposte Rule 的 +500% 减压施加量 Buff，基础全体减压5点仍为5点；将同一修正 Buff 的 Rule 改为 always 后，结果为30点。该结果在反击三要素引出减压 Effect、反击三要素 Effect 写法，以及直接把减压 Effect 写入反击技能定义的对照中均保持：riposte 不修正，always 生效。

本项只覆盖反击减压与 stress_heal_percent / stress_heal_received_percent 这类压力治疗两端修正；其他属性是否也不受 riposte Rule 影响仍未知，不得由此推广。涉及具体反击减压设计时，应把该特殊边界作为待核对的调用限制。本补录依据第109条原表测试及当前用户2026-11-04确认，未新增实机测试。

## `+100%` 暴击不是必定暴击
技能暴击修正和角色面板暴击可能为负数，因此“`+100%` 暴击”只表示增加 100 个百分点，不能称为必定暴击。要宣称必定暴击，必须证明最终暴击率在所有预期负修正后仍达到保证成功的范围；社区保守表述通常至少使用约 `+200%`。
