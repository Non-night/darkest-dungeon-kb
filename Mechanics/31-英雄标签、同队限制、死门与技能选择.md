## 英雄死亡的俗称

知识库编写者明确说明（2026-11-02）：“脖子一歪”指英雄死亡。解析聊天、需求或战斗描述时应按英雄死亡理解；本条只记录术语含义，不指定死因、击杀方式或死亡结算时序。

## 脚步轻重
英雄 Info 使用：

```darkest
tag: .id "light"
```

或：

```darkest
tag: .id "heavy"
```

分别声明轻型和重型脚步。常规职业设计通常只需正确选择轻/重标签，不必为原版不明显的脚步声制作额外表现。

## 信仰标签
- `tag: .id "religious"`：有信仰。
- `tag: .id "non-religious"`：无信仰。

该分类只干涉能够按宗教条件筛选目标的扎营技能，不改变战斗属性。设计写“信仰：无”时，应使用 `non-religious`，而不是完全省略标签。

## `id_index`
```darkest
id_index: .index 6
```

该索引用于英雄脚步声 ID。结合音频资源可以制作自定义脚步，但当前知识库尚未整理“每个 index 对应哪名原版英雄”的完整对照。一般设计只需先保证轻/重标签正确，再按模板保留所选 index。

## 区域建筑 tag
`training_ring`、`library`、`outsiders_bonfire` 等 tag 还可以决定英雄享受哪座区域建筑；见：[区域建筑与英雄标签](29-区域建筑与英雄标签.md)。同一个英雄可以同时具有脚步、信仰、区域建筑和其他功能 tag。

## 不可同队
常用模板：

```darkest
incompatible_party_member: .id aaa_limit .hero_tag aaa
```

- `.hero_tag` 匹配不可同队目标英雄已有的 `tag:`。
- 社区习惯把该 tag 写成英雄职业 ID，并在英雄自身写 `tag: .id "aaa"`。
- `.id` 的独立内部语义尚未完全明确；常规写法按 `<hero_id>_limit` 命名并仿照原版结构。

## 特殊配队名称

- `shared/party_name/party_name_library.json` 的 `party_names` 列表用字符串 `id` 和有序的 `required_hero_class` 数组定义队名对应的四个职业。保留数组顺序与重复职业。原版有同一组四职业按不同顺序分别定义不同队名的例子。
- 官方鞭笞者和破盾者 DLC 在同一相对目录下分别有 `flagellant.party_name_library.json`、`shieldbreaker.party_name_library.json`。原版显示名在 `localization/party_names.string_table.xml`，条目 ID 为 `party_name_<id>`。这些是本体及 DLC 中可核对的路径和格式。Mod 自定义前缀文件的扫描、同 ID 优先级及新增条目运行效果尚待测试。
- 完整中英文名和职业顺序见[原版特殊配队名称速查表](../Reference/vanilla_party_names.md)。

## 不可被反击
技能字段 `.can_be_riposted` 表示“该技能能否被反击”：

- `.can_be_riposted true`：可以被反击。
- `.can_be_riposted false`：不可被反击，即无视反击。

## 心力衰竭术语
- **心力衰竭**是该游戏机制的专有名词。
- **心衰**是“心力衰竭”的简称，两者指同一机制。
- 文档首次引入该机制时应写“心力衰竭（简称心衰）”；后文可以使用“心衰”。不得把这里的“心衰”解释成另一种独立状态。

## 死门三类 Buff
```darkest
deaths_door:
    .buffs <进入死门时 Buff>
    .recovery_buffs <普通治疗离开死门时 Buff>
    .recovery_heart_attack_buffs <心力衰竭进入死门后恢复时 Buff>
```

- 英雄生命降到 `0` 时不会立即死亡，而是进入死亡之门，并获得 `.buffs`。
- 英雄受到治疗、生命从 `0` 恢复到正数时，死门 Buff 消失并获得 `.recovery_buffs`。
- 再次进入死门时，普通死门恢复 Buff 消失并重新获得死门 Buff。
- 折磨英雄因常规加压达到 `200` 压力时触发心衰。触发前未处于死门时，执行心衰减压，生命降到 `0`，英雄以心衰状态进入死门。
- 折磨英雄已处于死门时触发心衰，立即死亡，跳过死亡抗性判定，死亡不可阻挡。进本等级差加压及部分直接设置压力值的特殊路径可以达到 `200` 而不触发心衰。详见[心衰判定](21-美德与压力机制.md#折磨达到-200-压力时的心力衰竭)。
- 由心衰进入死门后再恢复到正生命时，获得 `.recovery_heart_attack_buffs`，不是普通 `.recovery_buffs`。
- 死门 Buff、普通死门恢复 Buff、心衰恢复 Buff 三者互斥：至多存在其中一种；后出现者替换先出现者，均不叠层。

## 技能期间进入死门的判定
英雄在一段技能处理期间，因真伤或其他常规生命归零原因进入死亡之门时，死亡之门相关 Rule 与状态判定即时响应；目前未发现需要等待后续时序层、动画或 Update 的延迟。依赖“目标刚进入死门”这一状态的后续逻辑仍须同时核对自身的 AWR／`queue false`／`queue true` 时序。

### 最大生命值降低到零的例外
- 英雄受到最大生命值减益、使新的最大生命值低于当前生命值时，当前生命值会同步下降至新的最大生命值。
- 若该同步降低使英雄当前生命变为 `0`，当前测试显示**不会**给予死亡之门 Buff；因此也不能把这种最大生命值变化直接等同于普通伤害、真伤或心衰导致的“进入死门”。
- 这条最大生命归零路径大概率也不调用 `deaths_door: .buffs` 所引用的进入死门 Effect，但后半项尚未有独立的完整验证。设计上不得依赖它作为进入死门触发器；需要该触发器时应使用已有确认的常规生命归零路径。

## `activated_first` 与 `activated_last`

这两个 Rule 只按英雄的行动顺序判定，不计入怪物的行动；被心控并位于怪物侧的英雄仍计入。单刷时英雄的天然回合同时满足 `activated_first` 与 `activated_last`；获得额外回合后，`activated_first` 变为假而 `activated_last` 仍为真。战斗外不存在行动顺序，二者均不生效。

```json
{"rule_type":"activated_first","is_false_rule":false}
{"rule_type":"activated_last","is_false_rule":false}
```

因此，用二者同时为真来表达“单刷”时，实际只覆盖单刷的天然回合，不覆盖额外回合。怪物速度不会改变这两个 Rule 的英雄侧顺序判定。

## 技能选择
```darkest
skill_selection: .can_select_combat_skills true .number_of_selected_combat_skills_max 4
```

- `.can_select_combat_skills true`：允许玩家自由配置已解锁的战斗技能；最大同时携带数由 `.number_of_selected_combat_skills_max` 决定。
- `.can_select_combat_skills false`：不允许自由配置，英雄强制携带全部技能；即使总技能数超过最大可选技能数，也仍是全部携带。
- 出于安全和界面兼容，强制全技能时仍建议填写最大可选技能数，并使其不小于英雄总技能数。

## 心控预期站位
```darkest
controlled: .target_rank 1
```

该字段疑似决定英雄被心控并移动到怪物侧后优先抵达的站位。被心控单位仍具有英雄性质；跨侧后的目标、抗性和 Buff 规则尚需结合心控专项知识处理。该站位作用目前保留为“疑似”，不扩展为已确认的完整心控移动算法。
