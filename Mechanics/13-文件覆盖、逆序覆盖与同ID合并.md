## blockable Effect 的 Trait 前置条件
美德与折磨定义位于：

```text
shared\trait\*.trait_library.json
shared\trait\trait_library.json
```

对应 trait 的 `reaction_act_outs` 必须包含：

```json
{ "id": "block_effect", "data":{ "effect": "BarkStressHeal" }, "chance": 1}
```

- `chance` 必须大于 `0`，`.affliction_blockable_chance` 或 `.virtue_blockable_chance` 才具备正常运行的前置条件。
- 当前不确定任意正数是否均可，或是否必须为 `1`；保守创作统一写 `1`。
- 未建立全英雄自定义美德/折磨体系时，必须检查所有最终可能被随机到的条目；自定义定义中 `generate_chance_modifier > 0` 的条目不可遗漏。
- 原版八种折磨虽有 `block_effect`，但 `chance` 均为 `0`：`DarkestDungeon\shared\trait\trait_library.json:78`、`:158`、`:238`、`:318`、`:395`、`:475`、`:554`、`:635`。因此未完整补充折磨定义时，禁止使用 `.affliction_blockable_chance`，否则可能崩溃。
- 原版五种美德的 `block_effect.chance` 均为 `1`：`DarkestDungeon\shared\trait\trait_library.json:711`、`:787`、`:863`、`:939`、`:1015`。在没有 Mod 修改原版美德时，`.virtue_blockable_chance` 可正常使用；若发生覆盖，必须重新检查。

## 普通同路径覆盖
绝大多数文件只有在相对路径和文件名完全一致时才会相互覆盖。通常顺序为：

```text
高优先级 Mod > 低优先级 Mod > 原版
```

`dlc` 目录下文件的覆盖规律目前不明确，不得直接套用普通规则。

## Info / Art / Override 的整文件覆盖

`*.info.darkest`、`*.art.darkest`、`*.override.darkest` 属于同路径同文件名整体覆盖，不是只替换写出的技能行。范围包括英雄、怪物及其他 Info 类对象。修改时须保留低优先级文件中所有未修改定义；只有目标行的补丁文件会丢失其他内容。推荐复制完整文件再修改指定部分。文件内同 ID 分行的解析规则与跨来源整文件覆盖是两件事。依据知识库编写者明确纠正，详见[Mod 文件覆盖要求](24-Mod识别与职业Mod目录结构.md)。

## Effect 文件的同名叠加例外
迂回表第88条 P1424–P1427/X1718–X1721 明确指出：跨 Mod 的同名 Effect 文件仍参与叠加，不遵循普通同路径同名文件的高优先级完全覆盖规则。不能通过另一个 Mod 中的同名 Effect 文件让旧定义消失；补丁及额外组件须检查实际同时加载的定义与重复执行。当前用户于2026-11-04确认按原表修正；非本轮新增实机测试。此项仅适用于 Effect 文件，不推广到其他文件类型。Effect 分行、逻辑身份与施加顺序见[专题18](18-Effect同名与分行.md)。

## 已知逆序覆盖

### 饰品文件与重复 ID 是两层选择

| 竞争对象 | 优先级 |
|---|---|
| 同路径同名的整份 `trinkets\*.entries.trinkets.json` | 高优先级 Mod > 低优先级 Mod > 原版。生效的是整个文件。 |
| 不同已加载饰品文件中重复的 `entries[].id` | 原版 > 低优先级 Mod > 高优先级 Mod，即条目选择取较低优先级。 |

修改本体原版饰品时，将定义它的整份 `trinkets\base.entries.trinkets.json` 按原路径和原文件名复制到 Mod，只编辑目标条目，保留同文件中其他条目。把原版同 ID 条目另写到自定义前缀文件，原版定义仍在竞争中，调整 Mod 优先级无法让新文件中的同 ID 条目替代原版。新增饰品可用自定义文件名前缀及唯一的饰品 ID。两个 Mod 都在同路径放了整份文件时，高优先级 Mod 的整份文件胜出。

证据是[当前用户于 2026-11-21 的纠正与追补](../Sources/tutorial_corrections_20261121.json)。适用范围是饰品。本轮未重新启动游戏。`dlc` 下的覆盖细节仍按各自资料处理。

### 物资和庄园物品的历史记录

旧版把饰品和下列两类放在同一个“逆序覆盖”表下，未区分整文件与同 ID 条目。饰品部分以上面的分层为准。下列两类保留旧表记录，适用层级待核对。

- `inventory\*.supply.inventory.items.darkest`
- `inventory\*.estate.inventory.items.darkest`

```text
低优先级 Mod > 高优先级 Mod > 原版
```

`inventory` 中其他文件的覆盖顺序暂不明确。

## 本地化格式优先级
本地化冲突先比较格式：`loc` 高于 `loc2`，该跨格式覆盖无视 Mod 优先级；只有双方均为 `loc` 或均为 `loc2` 时才依照 Mod 优先级。详见：[loc 与 loc2 本地化覆盖优先级](16-loc与loc2本地化覆盖优先级.md)。

## 同 ID 高覆盖低
部分文件不是整文件互斥，而是按条目 ID 合并：同 ID 时高优先级覆盖低优先级，不同 ID 可共存。美德/折磨定义属于此类：

```text
shared\trait\*.trait_library.json
shared\trait\trait_library.json
```

因此修改某个原版美德或折磨时，应复用其 ID；新增不同 ID 不会替换原条目。

## 怪物容器释放效果分行与结算时序

同一个怪物 Info 内，`captor_full:` 的不同字段可拆行共同生效。**重复写多行 `captor_full: .release_effects` 会向同一释放效果列表追加 Effect ID**，已按实测确认。分行后的总容量、重复 ID 与跨行执行顺序待测。Abigail Williams 案例也确认 `battle_modifier: .living_other_enemy_buffs` 可在同一文件多行追加。

`KadathFull` 满容器自杀触发变为空容器 `KadathEmpty_G` 并释放被捕获的阿比盖尔，随后 `.queue true` 的 `AW_KF_Clear` 按 `KadathEmpty` 类型清掉空容器。该 Effect 的实际结算晚于容器变身。延迟死亡的 size0 再以独立时序召唤二重幻影，填回空容器留下的 size1 位置。其他 `.queue` 写法的相对时序待测。
