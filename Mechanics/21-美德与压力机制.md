## 模式每回合压力与眩晕空过

英雄 `mode:` 定义中的 `.stress_damage_per_turn` 表示该模式的每回合压力，例如原版咒缚的兽形模式。英雄因眩晕而空过回合时，不触发该字段所配置的模式每回合加压。该边界仅限此模式字段，不能推广为所有回合加压、DOT 或冷却都不触发，也不据此推断主动跳过回合或怪物持有者的对应表现。

证据：迂回表第46条 P1093/X1270–P1094/X1271，当前用户于2026-11-03确认补入；非本轮新增实机测试。字段形式及原版实例见 [Info.mode](../Info/headers/Info.mode.md)。

## 压力范围与美德判定
- 常规压力范围为 `0`～`100`。
- 常规加压结算至 `100` 压力时进行美德／折磨判定，默认概率为 `75%` 折磨、`25%` 美德。
- 等级差带来的一次性进本压力只增加压力值。即使进本后正好是 `100`，也要等到下一次实际加压才触发美德／折磨判定。修改全局规则后，若某次加压或减压的最终量被压到 `0`，这两种情况是否会触发判定各自待测。[原版进本压力表](../Reference/vanilla_raid_tables.md#低等级英雄进本的一次性压力惩罚) · [知识库编写者补充](../Sources/starting_stress_affliction_check_20261125.json)
- 进入美德后，压力范围扩展为 `0`～`200`。
- 美德状态下压力达到 `200` 时，美德消失，压力归零。

## 折磨达到 200 压力时的心力衰竭

处于折磨的英雄在常规加压结算中达到 `200` 压力时，触发心力衰竭（简称心衰）。

- **触发前不在死门**时，执行心衰减压，生命归零，英雄以心衰状态进入死门。
- **因心衰进入死门后**，生命由治疗恢复到正数并脱离死门时，获得英雄 Info 的 `deaths_door:` 下 `.recovery_heart_attack_buffs` 指定的心衰恢复 Buff。普通死门恢复 Buff 由同一 Header 下的 `.recovery_buffs` 定义。原版十字军两项均见 `heroes/crusader/crusader.info.darkest:52`。
- **触发前已在死门**时，英雄立即死亡。死门心衰跳过死亡抗性判定，死亡不可阻挡。
- **进本等级差加压**只更新压力值，即使到 `200` 也不会触发心衰。部分直接设置压力值的特殊路径也有此行为，具体适用路径待逐项确认。

[知识库编写者补充](../Sources/heart_attack_threshold_20261125.json) · [心衰恢复减益](67-死门恢复与心衰恢复减益.md)

## `shared\trait\*.trait_library.json` 中美德/折磨的定义格式

原版及官方 DLC 的美德、折磨定义位于：

```text
shared\trait\trait_library.json
shared\trait\*.trait_library.json
```

文件根对象使用 `traits` 数组；每个数组元素是一个 trait 定义。当前已读取的原版样本包括基础库、猩红庭院的 `flagellant.trait_library.json` 和火炬之光的 `color_of_madness.trait_library.json`。

常见骨架为：

```json
{
  "traits": [
    {
      "id": "trait_id",
      "is_generated": true,
      "overstress_type": "affliction",
      "curio_tag": "none",
      "curio_tag_chance": 0.0,
      "keep_loot": false,
      "generate_chance_modifier": 0.0,
      "buff_ids": [],
      "combat_start_turn_act_outs": [],
      "reaction_act_outs": []
    }
  ]
}
```

原版已确认的字段与边界如下：

- `id`：trait 的 ID。基础原版库中，`overstress_type: "affliction"` 的条目是折磨，`overstress_type: "virtue"` 的条目是美德。当前资料未确认是否存在其他合法 `overstress_type` 值；大概率没有，不要自行扩展。
- `is_generated`：是否可以被自然刷出。写 `true` 时可以参与自然生成；写 `false` 时，只有在英雄 Info 的 `overstressed_modifier` 中明确指定该美德/折磨的英雄才能获得它。这里的“自然刷出”与通过 Info 定向指定不是同一条路径。
- `overstress_type`：区分美德和折磨，已确认值为 `virtue` / `affliction`。
- `curio_tag`：英雄队伍路过奇物时，该 trait 可能强制让持有它的英雄主动互动的奇物类型。
- `curio_tag_chance`：上述奇物主动互动的概率。按百分比概率理解，原版静态值使用 `0.25`、`0.5` 等小数表示；当前未进一步确认引擎允许的精确上下限，不能把字段上限或小数换算细节写死为已验证公式。
- `keep_loot`：与上述 trait 引发的奇物主动互动配套；原版相关结构中可写 `true` 或 `false`。本次原版 trait 文件读取只确认字段存在，不能仅凭 trait 文件进一步扩展其玩家侧战利品语义；需要使用时另查奇物/怪癖专题。
- `generate_chance_modifier`：作用尚未确认。已知火炬之光的 `color_madness` 写 `-1.0`，其自然生成权重确实低于其他折磨；但不能据此确认 `-1.0` 一定代表排除常规生成，也不能把该值直接当作布尔开关或固定百分比。
- `required_dungeon_history`：表示只有去过对应地区的英雄才能获得该美德/折磨。多个值之间的组合关系尚未确认；不要自行断言是 AND、OR 或其他逻辑。该字段不是“当前所在地区”的同义替代。
- `buff_ids`：该 trait 获得后提供这些 Buff，并从获得美德/折磨开始持续到该美德/折磨消失。数组中的 ID 是 Buff 引用，不是本地化文本 ID。

### `combat_start_turn_act_outs`

该字段是回合开始时 `act_out` 候选列表。单个条目的一般结构为：

```json
{
  "id": "attack_friendly",
  "data": {
    "number_value": 0.1,
    "string_value": "EffectOrBarkId"
  },
  "chance": 1
}
```

部分 `id` 可以追加自己的条件字段，例如 `attack_friendly` 可使用 `valid_hero_class_ids`，`retreat_from_combat` 可使用 `raid_limit`。同一 trait 内可以多次写相同的 `id`，只要附加条件不同；火炬之光的 `color_madness` 就为不同英雄职业分别写了多条 `attack_friendly`。

这里的 `chance` 不是独立百分比，而是该条回合开始 `act_out` 的相对权重。并且，美德、折磨和怪癖的回合开始 `act_out` 共享同一个候选池：只要其中任意一个美德、折磨或怪癖的 `combat_start_turn_act_outs` 放入了权重极大的 `nothing`，就可能压低到使该英雄身上其他美德、折磨和怪癖的回合开始 `act_out` 都不触发。具体权重归一化和“极大”的数值边界尚未确认。

每个英雄每次回合开始，至多触发该候选池中的一项 `combat_start_turn_act_outs`。这是回合开始型 `act_out` 的单次触发数量边界，不扩展为反馈型 `reaction_act_outs` 或其他额外行动的次数限制。依据迂回表第92条 P1455/X1767，当前用户于2026-11-04确认；非本轮新增实机测试。

原表第92条 P1465/X1784 将回合开始型 `act_out` 的 `chance` 记为 float，并以约 `3.402823e38` 作为表示上限，给出 `nothing` 使用 `1000000000000` 量级权重的方案示例。这里的 `1e12` 只是原表方案取值，不是必需下限或通用安全阈值；它只能把其他候选项的触发概率压到很低，属于近似压制而非绝对免疫，实际残余概率仍取决于候选池。该相对权重说明不推广到使用百分比概率的反馈型 `reaction_act_outs`。当前用户于2026-11-04确认按此边界补入，非本轮新增实机测试。

对确实能被自主行动调用的无动画翻页技能，美德、折磨、怪癖引发的回合开始型 `act_out` 中，虚拟道具仍会正常执行，不能用规避心控卡死的同一方案避免自主行动卡死。原表采用极大权重的 `nothing`，使当前英雄免疫其他非自身的回合开始型 `act_out`，以避免自主行动调用该类技能；代价是同时抑制其他非自身怪癖／疾病的相关回合开始设计，并非只屏蔽不想要的自主行动。此处“非自身”保留原表的方案用语，不补造按用途隔离的能力。 该应用经当前用户于2026-11-03确认，来源为迂回表第38条 P947/X1105；非本轮新增实机测试。官方移动例外、完整用途边界及代价见 [无动画翻页专题](76-无动画友方技能与skill-instant限制.md#自主行动的-nothing-方案与代价)。

`data.number_value` 与 `data.string_value` 是被选中 `act_out` 使用的两个数据槽；不同 `id` 对这两个槽的解释不同，不能把它们统一解释成概率或 Effect ID。

### `reaction_act_outs`

该字段是 trait 对事件/行为作出反应时的 `act_out` 候选列表。一般结构为：

```json
{
  "id": "comment_self_hit",
  "data": {
    "effect": "BarkStress"
  },
  "chance": 0.33
}
```

- `chance` 是百分比概率，不是与 `combat_start_turn_act_outs` 共用的权重池。
- 该概率存在上限，且上限低于 `100%`；具体上限目前未知。
- `data.effect` 是该反应使用的 Effect/Bark ID；不同 `id` 的数据字段由各自 act_out 类型决定。

### 当前原版样本概览

基础原版 `trait_library.json` 当前包含 8 个折磨和 5 个美德；官方 DLC 的指定 trait 文件又提供了 `berserk` 折磨和 `color_madness` 折磨。基础原版美德的 `overstress_type` 均为 `virtue`，基础原版折磨及这两个 DLC 条目均为 `affliction`。

上述格式和已确认行为来自原版/官方 DLC 文件与当前用户补充。`generate_chance_modifier` 的完整算法、`required_dungeon_history` 多值逻辑、`reaction_act_outs.chance` 的精确上限以及其他 `overstress_type` 值仍应保持未知。

## `.clearvirtue`
- `.clearvirtue 1` 直接移除目标的美德；`.clearvirtue 0` 等同于未填写。
- 清除美德不会立即改变压力值。若目标压力为 `120`，清除后仍为 `120`，会暂时处于压力高于 `100` 但既无美德也无折磨的状态。
- 已有社区测试记录观察到：若清除后压力高于 `100`，目标下次受压时压力会被强制复位为 `100`，随后重新进行美德/折磨判定。
- 该重新判定过程中，美德判定与折磨判定所使用的具体压力值处理尚未完全确认。
- 清除美德是否等同于驱散美德源，尚未确认；不要据此替代已确认的 Buff 源清除机制。

## 尚未确认的减压边界
- 清除美德后，若进行减压但减压量不足以使压力降到 `100` 以下，是否同样先将压力强制为 `100` 并重新判定，尚未确认；创作时应避免依赖。
