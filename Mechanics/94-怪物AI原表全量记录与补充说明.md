## 知识库编写者补充：冷却与眩晕（2026-10-28）

本条来自当前用户在本维护会话中的明确说明，入库后作为知识库编写者确认保存。
**怪物 AI 技能冷却按小回合（单位自身的一次回合）计数，不按大回合计数。眩晕是‘结束回合’，不是‘不判定回合’，因此眩晕空过的小回合仍按正常回合处理冷却，不额外排除。**
这条确认针对冷却与眩晕的小回合处理，不据此把 `performing_turn`、`performing_turn_min/max` 的全部累计／重置边界一并写成已确认；原表 Skill Selection 第25行‘眩晕空过的回合似乎未计数’仍保留为原始资料措辞，不混同为冷却规则。
额外行动另有 `is_cooldown_enabled` 与 `decrement_combat_skill_id_override_cooldown`，原表分别解释触发冷却与递减冷却；不能把普通小回合确认扩展成‘所有额外行动必定递减冷却’。

## 整轮最后行动者触发小回合前后额外行动

迂回表第87条 P1397/X1685 的时序观察：整轮最后行动者仍可触发小回合前／后 AI 额外行动，不因本轮已无剩余常规行动而必须等待下一整轮。当前用户于2026-11-04确认按此边界补入；非本轮新增实机测试。其他 AI 触发条件和可用技能条件仍须满足，不推广到其他额外行动窗口、无合法技能或任意流程均保证释放。

## 大回合前后的共享技能位置

迂回表第87条 P1398/X1686：全场每个整轮有一个共享的“大回合前”技能位置及一个共享的“大回合后”技能位置；多个 AI 使用这些窗口时会竞争或占用，普通怪物、召唤物可能占用位置而干扰 Boss 的特殊机制。这不是每个怪物各自独享的位置，也不表示每轮必须实际释放一个技能。竞争优先级、冲突选择算法及其他额外行动窗口的容量未由此确认，不补造。当前用户于2026-11-04确认按共享槽位及干扰边界补入；非本轮新增实机测试，不把原表普通用途一概不用的建议写成通用禁令。

- `preferred_skill`、`ally_controlled_skill`、`next_initiative_target`、`ignore_desires_on_single_valid_skill` 等依照原表保留疑问或无实例边界，不补造确定行为。

- Skill and Target Parameters 第79～82行中，`enemy_rank_target_heroes_*` 与 `non_enemy_rank_target_heroes_*` 的中英文‘标记／未标记’对应存在相反表述，真实语义待确认。

## 原版格式对照：JSON 层级、数组与冷却对象

文件使用 `raid/ai/<前缀>.monster_brains.json`，不是 `.darkest` Header 语法。实际前缀可含点，例如 `additional.color_of_madness`。单位通过 `monster_brain: .id <AI_ID>` 引用数组内的 `id`，不是通过文件名引用；Info 入口参见 `Info/headers/Info.monster_brain.md`。

| JSON 位置 | 官方已见类型与结构 | 边界 |
|---|---|---|
| 根对象的 `monster_brains` | 数组，每项为独立 AI 对象 | 不直接以 AI ID 作为根键 |
| AI 对象的 `id` | 字符串 | 原版 `default` 是确有定义的 ID，不是占位符 |
| AI 对象的 `skill_cooldowns` | 数组；每项是包含 `combat_skill_id` 字符串与 `amount` 整数的对象 | 空数组合法实例存在；已见 amount 有 0、1～8、9999，不据此限定完整值域 |
| AI 对象的 `skill_selection_desires` | 数组；每项有同级的 `type` 字符串和 `data` 对象 | 具体技能选择参数放在该项 data 内 |
| AI 对象的 `target_selection_desires` | 数组；每项有同级的 `type` 字符串和 `data` 对象 | 目标选择参数放在该项 data 内 |
| AI 对象的 `bonus_initiative_desires` | 数组；每项有同级的 `type` 字符串和 `data` 对象 | 无额外行动时官方有空数组实例 |
| AI 对象的 `ignore_desires_on_single_valid_skill` | 布尔值，与上述数组同级 | 不是 desire 的 type，也不是 data 内参数；已见 castellan_A/B 中为 false，不能仅凭名称确定 true 的算法 |

全部 223 个定义都写有 id 与上述四个数组，但这是出现规律，不证明全部键是引擎强制必填。实际扫描有 136 个冷却条目、697 个技能 desire、568 个目标 desire、43 个额外行动 desire；所有已见 desire 条目均为 type/data 二键结构。

证据定位：`raid/ai/base.monster_brains.json:1–94`（test、default、数组、type/data、冷却）；`dlc/580100_crimson_court/features/crimson_court/raid/ai/crimson_court.monster_brains.json:394,472`（AI 同级布尔字段）。本节是结构说明，不提供未经引用闭包验证的可运行 Mod 模板。

## 原版格式对照：值类型与相似字段不能互换

- 使用标准 JSON 的双引号、逗号与数组／对象括号；布尔值是 `true`/`false`，不是字符串、True/False 或 1/0。禁止尾逗号，不把 `.darkest` 的点前缀、Header 或注释搬进标准 JSON。新建／改写配置保存 UTF-8 无 BOM。
- `base_chance`、`per_round_chance` 以及已见生命比例字段为 JSON 数值，不写 `%`；数量与行动次数参数在已见实例中为整数。官方 base_chance 有负值和大于 1 的值，因此不得套用 Effect 的百分比规则或直接当最终概率。数值书写类型不证明全部取值范围或引擎强制类型转换规则。
- `valid_ranks` 是字符串，例如 `"43"`，不是数字 43 或数组 [4, 3]。证据：猩红庭院 AI 文件第430、508行。
- `combat_skill_id` 用于技能选择 data 或冷却对象；`specific_combat_skill_id` 用于目标选择 data；`combat_skill_id_override` 用于额外行动 data。不能统一替换名称。官方 specific_combat_skill_id 有空字符串实例，不擅自解释所有省略字段的默认值。
- 原表 `min/max` 表示两个不同键，例如 hp_ratio_min 与 hp_ratio_max；斜杠不是 JSON 键名的一部分。原表称必需／推荐的参数仍按原表证据等级保存，不能仅由静态出现率证明引擎必需。
- `hp_ratio_threshold` 与 `health_ratio_threshold` 都是官方拼写，但不是可互换别名：本体第57行 heal_skill 的 data 用 hp_ratio_threshold；第9503、9519行 hp_ratio_threshold 类型的额外行动，其 data 用 health_ratio_threshold。必须区分 type 的字符串值和 data 的键名，不能因原表写‘同上’就替换。
- `is_guarding`/`is_guarded` 同时出现在 performer_guard_skill 的技能 data 和 random_target/ally_class_target/guard_target 等目标 data；不得把原表‘怪自己’的解释跨上下文一律套用。官方配置确认位置不同，完整运行判断仍需按类型核对。
- 冷却仍按知识库编写者确认的小回合规则处理；结构核对不升级额外行动的触发时序、权重合并、排他冲突、performing_turn 累计／重置边界。

## 特殊用途：借陷阱抗性模拟嘲讽倾向（2026-10-28）

### 知识库编写者确认的行为与使用条件

本节来自知识库编写者在2026-10-28维护会话中的机制说明，并经当前用户确认按此范围入库；不是原表原文、原版已有嘲讽实例或本次新增实机测试。

对于战斗而言，陷阱抗性没有通常的战斗抗性作用，但仍能被抗性倾向 AI 识别。可在安排好的怪组中，降低某个英雄的陷阱抗性，让特定怪物所用 AI 的大多数技能在目标选择中带有低值陷阱抗性倾向，并调节该倾向的权重，模拟该英雄嘲讽值更高。

这里是‘借用陷阱抗性作为可读取的选敌指标’，不是新增独立的嘲讽属性，也不是以陷阱抗性抵抗普通攻击。方案依赖怪组及 AI 配合，不会让所有未改动的原版怪物自动偏向该英雄。

### 原版结构依据与证据边界

原版可核对的结构是 target_selection_desires 内的 resistance_target：data 含 resistance_type_id、is_greater_comparison、base_chance，以及 specific_combat_skill_id、敌友与排他字段。本体 `raid/ai/base.monster_brains.json` 的 siren（第1792行起）包含对 siren_song 的减益抗性倾向：resistance_type_id 为 debuff，较低方向的 is_greater_comparison 为 false、base_chance 为 3.0；较高方向则为 true、-1.0。

该实例只佐证抗性倾向的结构与已有取值，不冒充原版配置已有陷阱抗性嘲讽。陷阱抗性能被该 AI 识别、并可用于本方案的行为依据，是知识库编写者的明确说明。Info 的 `.trap` 拼写不直接充当 AI 的 resistance_type_id 取值证明；本次不在未经该取值单独核对的情况下输出可运行 JSON 模板。

### 调控目标、限制与未确认细节

- 在相关技能的目标选择倾向上调权重，提高低陷阱抗性英雄被选中的倾向；不是改变技能本身的使用频率，不保证最终概率与权重成线性关系。
- 这是概率倾向，不是强制集火，不保证命中、造成伤害或任何技能都能选中该英雄。仍受技能合法目标、站位、其他目标倾向及其筛选条件影响。
- AI 读取的是原始抗性、修正后值还是截断后的值，多个英雄同值如何选取，多个 desire 如何合并／归一化、负值如何处理，仍未确认。不要由本方案反推这些算法。
- 降低陷阱抗性的方案是否会影响战斗外的陷阱处理，取决于修改是否在战斗外持续；实际实现应检查施加范围与清理时机。这是设计安全检查，不是宣称所有实现均有该副作用。
- 保留既有冷却、眩晕与额外行动规则，不以本方案改写原表或把未知字段升级为确定结论。
