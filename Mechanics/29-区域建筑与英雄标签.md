## 定义文件
猩红庭院区域建筑主体定义位于：

```text
DarkestDungeon\dlc\580100_crimson_court\features\districts\campaign\town\districts\districts_districts.json
```

当前版本该文件定义 11 座建筑：`spire_of_hope`、`bank`、`illuminators_guild`、`granary`、`buskers_corner`、`house_of_the_yellow_hand`、`altar_of_light`、`training_ring`、`library`、`theater`、`outsiders_bonfire`。

Fire's Edge 新增三座建筑，单独定义于：

```text
DarkestDungeon\dlc\4964110_fires_edge\features\fires_edge\campaign\town\districts\runaway_duelist.districts.json
```

分别为 `conservatory_of_steel`、`craftworks`、`archaeologic_salon`。因此不能假定所有官方区域建筑都集中在猩红庭院的单个文件。猩红庭院血库和农场区域建筑也各有独立定义文件。

## 通用结构
官方文件顶层常见：

```json
{
  "enabled": true,
  "buildings": []
}
```

单座建筑通常包含：

- `name`：建筑 ID。
- `render_data.sprite_paths`：建筑 Spine 骨骼和购买动画骨骼路径。
- `render_data.not_built_animation`、`built_animation`、`purchased_animation`：未建造、已建造、购买时动画名。
- `render_data.town_priority`：城镇界面排序。
- `currency_cost`：建造货币类型和数量。
- `buff_list`：建筑提供的效果数据。

不同 `buff_list.type` 使用不同字段，不能只复制 `DistrictHeroBuffData` 的结构去创建其他类型建筑。看不懂的建筑效果类型应按最接近的官方建筑完整仿写。

## `DistrictHeroBuffData` 与英雄 tag
职业享受某座英雄型区域建筑 Buff，取决于英雄 Info 的 `tag:` 是否命中建筑的 `hero_type_tags`。

训练场实例：

```json
{
  "type": "DistrictHeroBuffData",
  "name": "hero_buff0",
  "hero_type_tags": ["training_ring"],
  "buff_list": ["districts_training_ring_1", "districts_training_ring_2"]
}
```

英雄写：

```darkest
tag: .id "training_ring"
```

即会被训练场的 `hero_type_tags` 选中，并享受其 `buff_list`。其他原版职业专属建筑同理，英雄 tag 必须与建筑数组中的字符串完全一致。

- `house_of_the_yellow_hand` 对应 `house_of_the_yellow_hand`。
- `altar_of_light` 对应 `altar_of_light`。
- `training_ring` 对应 `training_ring`。
- `library` 对应 `library`。
- `theater` 对应 `theater`。
- 异乡人篝火使用 `DistrictCampingBuffData`，其 `hero_type_tags` 为 `outsiders_bonfire`；职业要获得额外扎营点，应具有该 tag。
- Fire's Edge 的决斗学院 `conservatory_of_steel` 有一组全体效果和一组仅匹配同名 tag 的专属速度效果。

`hero_type_tags: []` 在官方英雄型建筑实例中用于不限制职业，即对全部符合该建筑效果类型的英雄生效。

## 区域建筑 Buff 源
区域建筑施加的 Buff 使用 `bsrc_district`。不得因为职业 Info 写有建筑 tag，就把建筑 Buff 复制到职业自身 Buff 列表；建筑建成后由区域建筑系统提供。

## 存档溢出的历史风险与64位环境转述

64位主程序下的存档溢出表现尚未核验。当前用户于2026-11-03补充“据说64位主程序已很难发生这个问题”，仅记为未核验转述；具体程序及版本不明，不能写成已修复、绝不会发生或所有64位程序均有同样表现。

迂回表的历史风险记录：区域建筑 Buff 等在大量已招募、阵亡英雄数据中的累积，可使单个存档文件过大，主要涉及保存这些英雄数据的 roster 文件。P1002 记载，单文件大于约15–20MB时，读档或存档过程中可能发生写入失败、存档损坏，进而导致下次读档崩溃。约15–20MB只保留为原表风险量级，不作统一精确阈值，也不外推为64位版本的确定容量。

原表提出避免建造向大量英雄施加 Buff 的此类区域建筑、清理墓地数据作为规避方向；这不是所有区域建筑都危险的结论，也不保证清理墓地能恢复已损坏的存档。

证据：迂回表第40条 P983/X1151、P984/X1152、P1002/X1171，以及当前用户于2026-11-03提供的64位环境未核验转述。原表旧环境风险与该转述分层保存，非本轮新增实机测试。
