## 指定 Rule 在读档／重启时的移除

指定 Rule 的读档／重启移除：`monster_type_count_min` Buff 写 `remove_if_not_active: true` 时，读档会使其消失，即使场上仍满足条件；原表也明确类比 `has_quirk` 配置该字段为 `true` 时的重启消失现象。用于两 Buff 抵消时，若抵消项消失而 `always` 项保留，组合净效果会被破坏。本项仅覆盖上述指定 Rule 与 `true` 配置，不推广到全部 Rule，也不据此保证 `false` 配置永不消失；不把它解释为持续时间正常到期。证据：迂回表第33条 P898/X1050，当前用户于2026-11-03确认按此边界补入；非本轮新增实机测试。

## 合法值
`.buff_duration_type` 与 Buff 定义中的 `duration_type` 只使用以下 12 个已知合法值：

```text
round
combat_end
quest_end
quest_complete
quest_not_complete
activity_end
idle_start_town_visit
till_removed
none
before_turn
after_turn
after_round
```

非法参数会发生什么当前未确认；创作时不得使用合法表以外的值。

## 逐类型含义
| 类型 | 正常扣减时机 |
|---|---|
| `round` | 每次正常个人回合结束后减 1，又称“小回合” |
| `combat_end` | 每场战斗结束时减 1 |
| `quest_end` | 任务（副本）以任意结果结束时减 1 |
| `quest_complete` | 任务成功完成时减 1 |
| `quest_not_complete` | 任务未完成并结束时减 1；已知包括任务中撤退和队伍团灭 |
| `activity_end` | 英雄的城镇活动结束时减 1；不是区域建筑（蓝图建筑） |
| `idle_start_town_visit` | 英雄在城镇闲置并发生过周时减 1 |
| `till_removed` | 不按普通持续事件扣减，直至被移除 |
| `none` | 无；性质疑似与 `till_removed` 相同，但尚未确认完全等效 |
| `before_turn` | 个人回合开始前减 1；各种 DOT 默认使用该类型 |
| `after_turn` | 个人回合结束后减 1；目前未发现与 `round` 的区别，可暂时按等效处理 |
| `after_round` | 战斗整轮结束后减 1；脱战期间没有战斗整轮，因此不会流逝 |

## 回合开始时的流血腐蚀、怪癖进化与扣减顺序

知识库编写者于2026-11-06撤回此前“Buff的回合开始触发器（如 `turn_start_additional_effect_ids`）晚于 `act_out` 的回合开始行为（如 `combat_start_turn_act_outs`）”的结论；二者相对时序目前待测。此前已确认回合开始附魔早于流血、腐蚀等 DOT 伤害结算；当前用户于2026-11-11进一步补充“回合开始附魔应该确实早于愈合”，本库按该当前判断补入附魔早于愈合。本次未提供独立测试过程，不写成 Agent 新实测。该补充不确定附魔与 `act_out` 的先后，也不补造其他回合开始阶段的完整顺序。来源：`Sources/buff_turn_start_trigger_timing_20261105.json`。

结合2026-11-11当前用户的补充，现行记录的相对顺序为：**回合开始附魔 → 愈合结算 → 流血／腐蚀结算 → 怪癖自然进化 → `before_turn` Buff 持续时间扣减**。其中附魔早于愈合来自本次单独补充，不能仅由二者都早于流血／腐蚀这一旧前提推出。来源：`Sources/turn_start_before_regen_20261111.json`。回合开始附魔与 `act_out` 的相对位置待测，不纳入此处固定顺序。愈合早于流血／腐蚀及实际1点愈合保命已有独立结论，见[治疗源与真吸血](27-治疗源与真吸血.md)，此处不重复扩大其适用范围。

- 若本回合靠怪癖自然进化才获得魔免，来不及阻止此前已经结算的流血／腐蚀。
- `before_turn` 类型的怪癖进化时间修正 Buff 即使仅剩1回合，也会先参与本次怪癖自然进化，然后才扣减到期；不能仅因看到“回合开始扣减”就认定它在本次进化前失效。

依据迂回表第55条 P1162/P1164–P1165（X1361/X1363–X1364），当前用户于2026-11-03确认按这组先后与用途补入。本轮未新增实机测试。这里只给出已列机制的相对顺序，不补造完整回合开始执行链，也不推定燃烧、其他 DOT 或其他进化／移除机制的时序。

## 回合结束附魔早于小回合 Buff 持续时间扣减

知识库编写者于2026-11-08通过实测确认：**回合结束附魔（`turn_end_additional_effect_ids`）触发 → 小回合型 Buff 持续时间扣减**，包括 `round` 和 `after_turn`。不是先扣减／到期移除 Buff，再触发回合结束附魔。

测试一：技能普通 `queue false` 获得一个持续1回合、具有回合结束附魔的 Buff，附魔内容为自奶1；观察到自奶触发，说明该附魔 Buff 在本次结束扣减到期前仍能触发。

测试二：技能普通 `queue false` 获得一个持续2回合的同类附魔 Buff，并在同时序获得一个持续1回合、抑制该自奶的 Buff；首回合自奶未发生，说明回合结束附魔触发时，抑制 Buff 仍在有效期内，尚未因持续时间扣减而消失。这里记录自奶被抑制的表现，不据此判定附魔入口完全未调用。

知识库编写者说明：同一时序内的严格先后顺序及上述 Buff 的持续时间类型组合均经过实测，最终先后结论确定。**存在时序分离的施加方式未测试**；知识库编写者判断其不可能影响结论，该判断单独保留，不冒称已测。不能据此补造回合结束附魔与燃烧、ActorDot或其他 Trigger 的完整相对顺序，也不扩展为整轮型 `after_round` 的结论。

来源：`Sources/turn_end_additional_before_duration_20261108.json`；社区实测，Agent未自行执行游戏测试。

## Effect 型燃烧的持续时间与两类燃烧的结算

知识库编写者补充（2026-09-20），并在本次会话澄清适用范围：Effect 型燃烧没有普通流血/腐蚀那种“持续若干回合”的持续时间；Buff 型燃烧仍有其自身持续时间。燃烧层数在燃烧持有者完成行动后结算；该结算发生在 `round` / `after_turn` 类型 Buff 的持续时间扣减之前。因此，不能把燃烧层数的减少写成普通 `duration` 或 `duration_type` 倒计时，也不能按 `before_turn` DOT 的时机处理。

燃烧默认衰减与向下取整按既有记录；新版 `hp_dot_burn_decay_percent` 的正值改为提高衰减速度。此前正值减慢的公式、负值无效与衰减率0%～50%的限制已退休，不能沿用；新公式、负值边界与死亡野火交互未提供。

### Effect 型与 Buff 型燃烧的实例行为

**使用警告（知识库编写者明确要求，2026-11-01）：极度不建议使用 Buff 型燃烧；以转移并继续正常发挥燃烧作用为目的时，应避免对群偷取燃烧。其他目的须结合实际需求判断，详见下述适用边界。** 下述机制与 `amount: 0.99` 用途用于保留已知行为，不代表推荐采用这些实现。

知识库编写者本次会话提供以下实测结论（入库日期 2026-10-17；并非本次 Agent 重新进行的游戏测试）：

- Effect 型燃烧在施加时或随后 Update 时会把其 `duration` 强制为 `10000`；具体发生在施加瞬间还是 Update 尚未确认，但不影响后续按长期燃烧实例处理。Buff 型燃烧没有这一强制 `duration: 10000` 特性，因此不能把 Effect 型燃烧的无意义 `duration` 结论推广到 Buff 型燃烧。
- Effect 型燃烧在被施加时会发生合并。例如先施加 8 层、再施加 7 层，存档中表现为一个 15 层燃烧，而不是两个独立实例。合并究竟发生在施加瞬间还是 Update 后才反映在存档中，当前只确认存档观察结果，时间点不确定。
- 对群偷取燃烧没有“施加”过程；即使被偷取目标承载的是 Effect 型燃烧，被偷取的燃烧也不会仅因偷取而自动合并。知识库编写者补充（2026-11-01）：对群偷取后，只有正在发生结算的那个燃烧可以与后续燃烧发生合并；这一局部合并仍不能解决对群偷取燃烧的问题，因此以转移并继续正常发挥燃烧作用为目的时仍应避免对群偷取燃烧；其他用途按下述目的边界判断。不得将此解释为所有被偷取的燃烧最终都会合并；后续燃烧的具体来源与更细合并时点未进一步明确。
- 知识库编写者补充并限定（2026-11-01）：这里的“对群偷取”专指 Effect 自身的目标写为群体类型，不是按技能是否 AOE 判断；AOE 技能逐个目标调用对单偷取应无此处的群体偷取问题。避免对群偷取燃烧的建议针对以转移燃烧并继续正常发挥其燃烧作用为目的的用途，不是对所有群体偷取用途的禁令。若目的只需要“转移后存在”的状态，或另有不依赖正常合并与燃烧结算的目的，可结合具体需求接受。Agent 必须根据实际目标、相关机制及当前用户要求自行判断，不能将下列例子当作用途白名单，也不能把可接受某用途推广为群体偷取已无异常。
- 例如，size0 对英雄全体偷取燃烧后检测自身有无燃烧，或者先对群偷取再偷取自身以驱散，均可接受；后者大多数情况下不如直接对群治愈燃烧。这些只是说明性例子，不穷尽可接受用途。
- Buff 型燃烧无论如何都不会合并。未合并的多个燃烧在回合结束时只会触发第一个被施加的燃烧，并只衰减该燃烧的层数；未合并燃烧是否能被 `.dmg_per_burn_stack` 正常读取，当前未确认。
- Buff 型燃烧的 `amount` 落在 `[0, 1)` 时，回合结束会播放燃烧生效音效，但不造成伤害、不减少层数，也不会使该 Buff 型燃烧消失。因此，在其他燃烧施加前先施加 `amount: 0.99` 的 Buff 型燃烧，可以在其持续期间阻止后续燃烧造成伤害并阻止燃烧层数衰减；这是知识库编写者确认的实测用途；上述“不消失”仅指燃烧结算本身，不排除 Buff 正常持续时间到期。
- 燃烧无论是否合并，游戏内 Buff 栏描述都显示合计后的燃烧数值；`amount: 0.99` 的 Buff 型燃烧在 Buff 栏显示为 0 层燃烧。

`wildfire_apply_adjacent_targets` 是已记录的专门例外：当任一英雄持有该 Buff 时，Wildfire 的传播目标机制改为向相邻目标传播，现有记录将其描述为两个相邻目标。它不改变“燃烧致死时传播一半层数并向下取整”的基础层数描述；其与衰减速率 Buff 的组合边界仍需单独核对。

## 战斗中的个人回合与整轮
- 战斗开始时进入第一轮；每轮开始会计算速度顺序，并向单位发放其应得的行动点。
- 单位依次行动或跳过个人回合；英雄默认获得 1 个行动点，怪物行动点由其定义决定。
- 所有单位行动结束且行动序列中不再有行动点时，本轮结束并进入下一轮。
- `round` / `after_turn` 处理个人回合结束，`after_round` 处理上述整轮结束。
- 战斗外仍有个人回合概念，但没有战斗轮次，因此 `after_round` 在战斗外不会减少；若无战斗结束清除，该 Buff 可在脱战期间保留，重新进入战斗并完成整轮后才继续扣减。
- 禁用式冷却采用 `after_round` 时，若禁用 Buff 跨战保留且未被其他机制提前移除，可实现脱战不消耗冷却，重新进入战斗后按整轮继续扣减。此处仅说明基于禁用 Buff 的冷却用途，不推广到怪物 AI 自带冷却，也不提供完整实现。证据：迂回表第35条 P911/X1066，当前用户于2026-11-03确认按此边界补入；非本轮新增实机测试。
- 若正常回合结束流程被跳过，依赖个人回合结束扣减的持续时间可能不会减少。
- 若 Buff 在当前技能执行期间施加给当前行动者，此时个人回合尚未结束；`duration 1` 配合 `round` 或 `after_turn`，都会在该技能结束后的本次个人回合结束时减至 0，因此通常只覆盖当前技能至当前回合结束。
- 迄今未发现 `after_turn` 与 `round` 不等同的情况；目前两者按等效处理，包括上述技能期间施加 `duration 1` 的行为。
- 所受增减益持续时间修正或错误跳过回合结束可能改变上述结果；这些通常只出现在极端特殊设计中，常规创作无需为其增加复杂兜底，只有明确使用相关机制时才单独检查。

## 任务结束与完成
任务完成、任务中撤退和队伍团灭都会使副本结束，但只有成功完成任务属于 `quest_complete`；撤退或团灭属于 `quest_not_complete`。`quest_end` 不区分这些结果。

## `duration` 示例
`combat_end` 配合持续时间 2：

1. 在当前战斗中施加 Buff。
2. 当前战斗结束时，持续时间从 2 减至 1。
3. 下一场战斗结束时减至 0，Buff 结束并消失。

Effect 原版实例：`DarkestDungeon\effects\base.effects.darkest:765`。

```darkest
effect: .name "Crusader Bulwark 1" .target "performer" .curio_result_type "positive" .chance 100% .duration 1 .buff_duration_type combat_end .combat_stat_buff 1 .protection_rating_add 20% .on_hit true .on_miss true .queue true
```

## Effect 覆盖 Buff 定义
Effect 通过 `.buff_ids` 引用 Buff 时：

- Effect 的 `.duration` 覆盖 Buff 定义中的 `duration`；
- Effect 的 `.buff_duration_type` 覆盖 Buff 定义中的 `duration_type`；
- Effect 未填写对应字段时，才使用 Buff 自身的对应定义。

推测 `.buff_is_clear_debuff_valid` 也会覆盖 Buff 定义中的 `is_clear_debuff_valid`，但该覆盖关系尚未确认。创作时不要在 Effect 与 Buff 中填写互相冲突的值。

把持续时间与类型留给 Effect、而不写在被引用 Buff 中，是部分作者的常见书写习惯，不是强制规范或特别推荐。

## 未写持续时间时必须区分调用方

“未写 `.duration`”不能脱离调用方一概按默认三回合理解：

- 常规技能 Effect 施加增减益而未写持续时间时，当前资料按默认 `3` 回合处理。
- 道具 Effect 施加增减益而未写持续时间时，社区实测显示 Buff 面板为 `0` 回合，但不会在获得时立即消失；它会在**使用道具者的本次个人回合结束**时消失，实际近似 `round`／`after_turn` 的 `duration 1`。

后者既不同于常规技能未写持续时间，也不同于把 `duration 0` 明写在普通技能 Effect 中的已知边界。道具需要跨回合保留 Buff 时，必须显式写入目标持续时间和 `buff_duration_type`，不得依赖该隐式 `0` 回合表现。

## Effect 直接声明 `.duration 0` 的历史观察

迂回表第125条记录了直接在 Effect 中写 `.duration 0` 时，不同效果类别有不同表现；以下来自该表的历史测试。常规技能增减益的默认值已于 2026-11-27 复测，反击与守护仍保留历史证据状态。

- 反击图标不显示回合数。施加给施术者本人时，在施术者回合结束时消失；施加给其他目标时，在受术者回合开始时消失；若持续跨越整轮，尚未消失的反击也会在整轮边界消失。
- 守护图标不显示回合数；所有目标身上的该守护在施术者本人的回合结束时消失。
- 常规增减益的 `.duration 0` 不按0或-1回合处理，而按未写 `.duration` 的默认持续时间处理；原表记录该默认值为3回合。

以上三项及直接声明为0的标记、DOT行为均是各自不同的历史观察；不能互相类推。尤其是本段常规增减益的默认持续时间结论仅针对原表所述常规技能 Effect 调用，不推广至道具调用或持续时间修正结果。

## `buff_duration_percent` 的基础时长、加算与取整

`buff_duration_percent` 挂在施术者身上，修正持有者作为施术者新施加的 Buff，类似施术者侧的流血持续时间修正。归属由知识库编写者确认。下列计算和生命周期来自 2026-11-27 的常规技能自施测试，受测 Buff 为普通非 DOT Buff，按 `after_turn` 扣减。施加时确定计数，随后定向移除时长修正，先前施加的测试 Buff 仍保留已计算的计数。

1. **先确定基础时长 D。** 常规技能的简写 Effect `.duration` 对已测正小数先截去小数部分，`1.9` 按 `1`，`0.999` 按 `0`。完整 Buff JSON 的 `duration` 使用整数写法，`1`、`2`、`4` 按给定值。实测带小数点的 `1.0`、`1.00`、`2.0`、`2.00`、`1.9`、`2.1`、`2.9`、`4.1` 等均回退至默认 `3`。两条路径在本次常规技能测试中，省略或读成 `0` 的基础时长均用 `3`。Effect 显式覆盖完整 Buff 时遵循上节的覆盖优先级，冲突写法未在本轮复测。
2. **合计施术者当前生效的同类修正，再乘一次。** 原始时长为 `D × (1 + Σ amount)`。`amount: 0.25` 表示增加 25%。基础 `8` 同时受 `+25%` 和 `+50%` 修正得到 `14`。基础 `1`、`2`、`4` 受 `+900%` 修正分别得到 `10`、`20`、`40`。
3. **乘算后取整。** 正值按就近取整，实测 `1.25 → 1`、`2.5 → 3`、`3.75 → 4`、`0.25 → 0`。最终为 `0` 的普通 Buff 可以施加，本次个人回合结束时移除。直接定义为 `0` 在第 1 步取默认值，乘完后得到 `0` 保留到扣减时结算。基础 `4` 受 `−125%` 修正得到 `−1`，个人回合结束后仍以 `duration = -1`、`duration_type = after_turn` 留在存档。该实例的界面显示“持续至扎营”。据知识库编写者补充，`-1` 表示无限计时。实际是否在扎营时移除取决于 Buff 源类型及特殊类型的清除规则。一般 `skill` 源 Buff 会在扎营时清除，这也解释了此例的本地化文案。迂回表第 243 条同时把修正属性 `buff_duration_percent` 自身列入[扎营源自动清除例外](15-Buff源与真驱散.md#扎营有自动清除例外的-buff-类型)。该例外描述修正 Buff 自身的寿命，受它修正的新 Buff 仍按各自的源类型和清除规则处理。其他负整数及负半数如何处理仍待测。

旧术语表把低于 100% 的修正描述为永久持续。普通 Buff 应根据乘算与取整后的结果判断。基础 `4` 受 `−75%` 修正实测为 `1`，基础 `4` 受 `−100%` 修正实测为 `0`。据知识库编写者转述的社区反馈，反击、守护、标记也受 `buff_duration_percent` 影响，实际使用时可暂按同一公式估算。三者是否沿用普通 Buff 的基础时长读取、叠加、取整和边界处理仍待实测，各自的扣减与清除依其生命周期规则。DOT 是否受该字段影响仍待确认。

来源 [`Sources/buff_duration_percent_20261127.json`](../Sources/buff_duration_percent_20261127.json)。

## 施术者侧 DOT 持续时间修正
以下五种 `stat_type` 修正 Buff 持有者作为施术者所施加的对应 DOT 持续时间：

| `stat_type` | 对应 DOT |
|---|---|
| `hp_dot_poison_duration_percent` | 腐蚀 |
| `hp_dot_bleed_duration_percent` | 流血 |
| `hp_heal_dot_duration_percent` | 愈合 |
| `stress_dot_duration_percent` | 惊恐 |
| `shuffle_dot_duration_percent` | 扰乱 |

- 作用主体是 Buff 持有者，修正的是该单位作为施术者释放出去的对应 DOT；不是修改持有者受到的 DOT。是否会追溯修改目标身上已经存在的 DOT，尚未专项确认。
- 多个同类持续时间 Buff 的数值相互加算，再修正持续时间；`amount: 0.5` 表示持续时间增加 50%，计算产生非整数持续时间时四舍五入。
- 自 2026-08-19 更新后，这些修正不仅作用于 Effect 型 DOT，也作用于 Buff 型 DOT。
- 知识库编写者本次会话更正（入库日期 2026-10-17）：任意 DOT 的最终施加持续时间为负时，都无法成功施加。因此，负向 DOT 持续时间修正不再构成此前所述“产生永久 DOT”的安全问题；旧版负持续时间转为永久 DOT 的说法已被本结论取代。这里检查最终施加持续时间，不是仅凭修正 Buff 的 amount 为负判断施加失败；不得将此结论推广到普通非 DOT Buff。
- 总修正恰为 `-100%` 时，DOT 仍可正常尝试施加。施加成功后，持续时间为 `0` 的非燃烧 DOT 会生效一次后消失，因此其实际触发次数近似等同持续时间 `1`。
- 除燃烧外，上述 DOT 的默认持续类型都是 `before_turn`。不要把“持续时间为 0 仍生效一次”或上述五类修正规则擅自扩展到燃烧。

## 真实消失时机
`duration` 与持续类型只决定正常到期时机。Buff 还可能因以下条件提前消失：

- `remove_if_not_active`；
- `remove_on_battle_complete`；
- Buff 源自身的生命周期清除，例如某些来源在扎营、重启或其他特定阶段被清除。

### `remove_on_battle_complete` 的强制清除

当 Buff 写有：

```json
"remove_on_battle_complete": true
```

脱战清理检查会强制移除当时已在清理范围内且标记 `true` 的 Buff。战斗撤退也会触发该清除。该字段会越过“Buff 来自静态来源”的直觉：即使 Buff 是由饰品、怪癖等静态内容持续提供，只要该 Buff 定义本身写了 `true`，它仍可能在战斗结束时消失。因此，任何饰品 Buff、怪癖 Buff、职业常驻 Buff 或其他预期跨战斗保留／自动持续提供的 Buff，都必须专项检查此字段，不能照抄临时战斗 Buff 的定义。

- `true` 的作用不是普通持续时间扣减，而是战斗结束节点的额外强制清除条件；
- 撤退应计入该节点；其他脚本式强制终止战斗的边缘情况尚未确认；
- 饰品 Buff／饰品套装 Buff 因该字段被清除后，在不重启、也不重新装备饰品的情况下不会自动恢复；重新装备对应饰品会再次取得这些 Buff。知识库编写者于 2026-10-28 进一步确认：重新装备一定会重新取得该饰品提供的全部静态 Buff，不论此前因何种原因失去；重新取得后是否再次被清除，另按当时条件判断。完整边界见 [饰品静态 Buff 的重新取得与恢复边界](47-饰品条目定义与装备Buff.md#静态-buff-的重新取得与恢复边界)；
- 重进存档能否自动重新提供饰品 Buff／饰品套装 Buff，目前未知；其他静态来源 Buff 被清除后，重启或重进存档能否自动恢复，同样未知；
- `false` 与省略该字段是否在所有版本中完全等效、其严格默认值，目前尚未专项确认。

因此推算真实存续时间时，必须同时检查持续数值、持续类型、Buff 自身移除参数和 Buff 源。尤其不能只因 Buff 来自饰品、饰品套装或怪癖，就断言它一定会在下一场战斗重新存在。对于饰品及饰品套装，已知不重新装备时不会在后续战斗自动补回。

## 脱战自动技能与脱战结算的相对时序

`.battle_complete_combat_skill_id` 脱战自动使用技能时，由普通 `queue false` Effect 新获得的 Buff，即使写有 `remove_on_battle_complete: true`，也会在本次脱战后保留。 知识库编写者于 2026-11-24 补充。具体脱战原因、该 Effect 与各项清理的先后以及 `queue true` 的表现尚未单独确认。

迂回表第131–132条记录了不同脱战原因下的历史时序观察；以下结论限原表所述自动使用技能调用，不能推广为所有战斗结束脚本的统一顺序：

- 战斗胜利（包括无尽本胜利）时，先执行脱战自动使用技能，再执行其余脱战结算。
- 撤退（包括传送）时，先执行其余脱战结算，再执行脱战自动使用技能。原表明确列出的“其余结算”至少包括 `combat_end` Buff 的持续时间减 1，以及 `remove_on_battle_complete` 的自动移除判定。
- 撤退时，持续时间仅剩1场战斗的 `combat_end` Buff 会在自动技能执行前到期消失；自动技能中新施加的 `combat_end` Buff 已错过本次扣减，不会因本次撤退再减少一场。此项不适用于战斗胜利。

这些是原表历史观察。比较新获 Buff 是否被本次脱战清除时，优先采用本节的 `queue false` 观察。历史顺序适用于原表所测的结算项与调用条件。来源：迂回表第131–132条 P2031–P2045（X2617–X2638）。

## 用结束附魔自驱散以兼容持续时间修正

若要兼容「老 e 强化」一类会延长 Buff 持续时间的 Mod，可给禁用式冷却等需要准时消失的 Buff 加结束附魔。在预定的结束节点，用 `effect_chance` 作条件门、直接枚举阶段等写法控制清理 Effect，让 Buff 持有者按 ID 驱散自身的冷却 Buff，并清除相关辅助 Buff。这样仍存续的冷却 Buff 可以在原定时点被主动清理。若用辅助 Buff 记录进度，也要检查它是否会被同一持续时间修正拉长而改变清理时点。

如果冷却 Buff 本身不显示、只隐藏持续时间，或用自定义文本呈现持续时间，可在每条施加路径上先让施术者获得足够大的正值 `buff_duration_percent`，紧接着施加冷却 Buff，再按 ID 清掉这条临时修正。正值用于抵消其他 Mod 的负时长修正，使实际写入的时长保持为正且足以覆盖预定冷却，避免算出 `-1` 后进入无限计时。冷却进度仍由对应的回合、轮次或战斗结束附魔模拟，到点定向自驱散。此补偿写法由知识库编写者于 2026-11-27 提出，具体组合待实测。

- 按持有者的个人回合计时，使用 `turn_end_additional_effect_ids`。该附魔早于 `round`／`after_turn` 的持续时间扣减，技能中给自己施加时应核对施加当回合结束是否计入。已知撤退失败会跳过回合结束附魔。
- 按战斗整轮计时，使用 `round_end_additional_effect_ids`。它与 `after_round` 的持续时间扣减顺序需要单独核对。
- 按成功结束战斗计时，使用 `battle_finished_successfully_additional_effect_ids`。若设计还要求在撤退等其他脱战路径清理，应单独核对对应入口及 `remove_on_battle_complete` 的适用条件。

字段见[新版 Buff 触发器](96-新版Modding更新Buff技能地牢饰品怪癖.md#新版-buff-触发器force_negative2026-11-05)，清理见[定向驱散的作用域与用法](15-Buff源与真驱散.md#驱散溢出与-id-定向驱散)。该方案由知识库编写者于 2026-11-24 提出，具体 Mod 组合待实测。来源为 `Sources/end_enchantment_timed_cleanup_20261124.json`。

## 用回合结束附魔模拟限时禁锢

施加禁锢（`.immobilize 1`）时，同时给同一目标施加一个负责计时的回合结束附魔 Buff。两条 Effect 应在**同一目标上共享概率骰子，并具有相同的最终成功率**，这样两者才可同成同败。核对命中／未命中条件、实际施加率与过抗结果。到达预定的个人回合结束时，让目标身上的 `turn_end_additional_effect_ids` 对其持有者执行 `.unimmobilize 1`，并清理计时 Buff。

如果原禁锢先被解除，同一单位随后又受到另一条本应继续保留的禁锢，而旧计时附魔仍在，旧附魔到期时可能把新禁锢一并解除。可控制提前解除和重施禁锢的流程时，应一起核对对应计时 Buff 的清理。知识库编写者于 2026-11-24 提出该设计及干扰风险，具体组合待实测。概率边界见[概率骰子共享与隔离](51-Effect概率骰子共享与隔离.md)。来源为 `Sources/end_enchantment_timed_cleanup_20261124.json`。
