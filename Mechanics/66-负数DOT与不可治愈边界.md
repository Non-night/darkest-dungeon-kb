## 静态 DOT Buff 的 Rule 与转移生命周期

迂回表第112条 P1729–P1736/X2187–X2197 区分 DOT Buff 的常规条件用法与静态提供用法。对于原表所指愈合、流血、腐蚀、恐惧和延迟扰乱等 Buff 型 DOT：

- 常规条件用法写 remove_if_not_active: true，Rule 不成立时 Buff 立即移除；这使 Rule 能控制该 DOT Buff 是否存在。
- 静态用法（如怪癖或饰品提供的 DOT）若写 remove_if_not_active: false，原表观察为 Rule 不成立时 Buff 仍存在且仍触发其 DOT 效果，因此该 Rule 对该静态 DOT 的实际触发等效于 always。不能把普通统计 Buff 的“Rule 不成立时停用”直接套到这类静态 DOT。
- 静态 DOT 尤其容易受转移干扰。原表观察：怪癖提供的静态 DOT 被转移后，不会自行重新出现，直到重启或该怪癖因进化重新获得；饰品提供的静态 DOT 被转移后，不会自行重新出现，直到重启或重新脱穿饰品。

这些是原表对所述静态 DOT 来源的历史观察，不能推广到全部 Buff 来源、所有 DOT 类型或任意转移机制；本项不构成当前版本重新实测，也不改变一般 remove_if_not_active 语义和来源清理边界。证据：第112条 P1732–P1736/X2191–X2197，当前用户于2026-11-04确认按此边界补入。

## 同一 Effect 行多个 DOT 字段的互斥优先级

迂回表第113条记录：同一条逻辑 Effect 定义行同时声明 `.dotPoison`（腐蚀）、`.dotBleed`（流血）、`.dotStress`（恐惧）、`.dotShuffle`（延迟扰乱）与 `.dotHpHeal`（愈合）中的多个字段时，这些 Effect 型 DOT 互相冲突，只有优先级最高的一种生效；调整这些字段的书写顺序不会改变结果。原表给出的固定优先级为：

`腐蚀 (.dotPoison) > 流血 (.dotBleed) > 恐惧 (.dotStress) > 延迟扰乱 (.dotShuffle) > 愈合 (.dotHpHeal)`。

本条只覆盖上述五种 Effect 型 DOT 的同一 Effect 行冲突：Buff 型 DOT 不受这项互斥限制；Buff 型 DOT 仍按各自 Buff 定义处理，通过 `.buff_ids` 引用多个 Buff 时可依既有多参数分行规则拆分。标记与潜行 Effect 也不受此限制。`.dotBurn` 和未列出的其他 Effect 字段不在本结论范围内，不推断它们的优先级或互斥行为。原表第113条 P1745、P1754–P1755、P1764–P1765、P1770、P1783–P1792、P1794–P1798/X2211–X2291；当前用户于2026-11-04确认按此边界补入。本轮未新增游戏测试。
