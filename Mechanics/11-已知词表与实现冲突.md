## set_monster_class_clear_initative 拼写（已确认）
- **正确的原版字段是 `.set_monster_class_clear_initative`**。虽然 `initative` 不是标准英语拼法，但代码创作必须原样保留。
- 社区主术语表收录的 `.set_monster_class_clear_initiative` 是错误拼写，只可用于纠错检索，不得输出到 Effect 代码。
- 直接证据：游戏原版猩红庭院 `crimson_court.effects.darkest` 第 281、287、288 行均实际使用 `.set_monster_class_clear_initative true`。
- 知识库会把社区表错误行规范化并合并进正确词条，因此错误拼写不作为独立有效 Effect 计数。

## monster_type_count_min 取反值域
- 已收录资料对取反情形是否允许 `rule_data.float < 1` 存在不一致。
- 旧工作簿备注还同时出现“不计算 size0”和“会计算 size0”两种相互冲突的说法；后续专项实测确认普通情况下会计算仍在场的 size0，包括死而不僵的 size0。连续 set 后另有检测不可靠的例外：知识库编写者2026-09-19补充，绝大多数情况下该 Rule 无法正常检测这类对象；黑圣物存在生效案例但其他人无法复刻，条件未知。不得把普通计数结论外推到连续 set，也不把个例提升为可复用保证。详见[连续 set 执行链](28-spawn、生命反馈与size0执行链.md)。原工作簿冲突仍作为来源边界保留。
- 知识库采用更保守的创作规则：无论是否取反，均要求 `rule_data.float >= 1`。
- 已确认的英雄侧数量1、空类型字符串、取反的战斗内条件组合，见[英雄侧仅战斗内成立的 Rule 组合](03-chance与抗性.md)；不得把该具体结论重新降为未知。其他取反情形的完整引擎边界仍未全部确认，不能仅凭静态格式资料推断。

## 冲突处理协议
1. 不静默合并冲突。
2. 明确列出每个来源实际写法。
3. 区分“资料中记录的格式约束”与“游戏引擎实际行为”。
4. 游戏字段最终以原版直接证据与实机结果为准。
