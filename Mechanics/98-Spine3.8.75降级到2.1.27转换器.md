## 批处理与重新转换

据文档，入口没有 GUI，扫描的是**当前工作目录 `./`**，不应无依据等同于 EXE 所在目录：

- 有 `.skel` 而没有同名 `.json`：用 Binary Reader 与 JSON Writer 导出 JSON。这不是“读取任意高版本 skel”的承诺；降级入口针对的是3.8.75导出的 JSON。
- 有 `.json` 而没有同名 `.skel`：用修改的 JSON Reader 与 Binary Writer 执行降级写回。
- 同名 JSON 和 SKEL 同时存在：按集合差集跳过，不自动覆盖或重新编译。需重新转换时，应先备份并移走旧目标，再在工作副本中处理；不能因无输出就认定新 JSON 已被转换。

## 使用限制与未确认行为

### 版本精确匹配不是通用改标签方案

文档报告蒙皮识别、scale 缺省和 deform 读取依赖 `trueVersion == "3.8.75"`。因此本工具应按3.8.75这一目标版本理解，不能泛称通用 Spine 3.8／3.x 降级器。来源提出对其他版本手动改标签；这里保留原说法但不把它作为已验证使用方案：**改标签能触发某个分支，不足以证明其他版本的数据结构与语义兼容。**未进入分支的后果也应依实际使用了哪些特性区分，不能说任何其他版本的任何模型必然崩溃。

### 负整数与 drawOrder 分开理解

drawOrder 重排意图是从数据层消除需写出的负偏移；Writer 的循环条件则是另一层终止处理。`value != -1` 不等于入口拒绝负值，更不等于正确编码负整数。不能把“循环能退出”写成“负整数格式已正确转换”。具体编码输出与游戏读取行为本轮未验证。

来源对越界／冲突的分析与随附说明“图层可能消失”的提醒分别保留；不能据一段数组索引推测就认定已证明某次游戏贴图消失的原因，也不认证所有负 drawOrder 都能无损重排。

### shear 的可达路径尚未说明

原文同时称 Reader 不解析 shear，又断言设置 shear 帧会输出类型9并直接崩溃，缺少 Reader→内存时间轴→Writer 的可达链条。新增枚举／写入分支不等于已支持 shear；目前不能确定具体输入会被忽略、在转换阶段报错，还是输出不兼容数据。此处保留“不要使用 shear”的工具使用约束，但不把原文的必然崩溃路径写成已证实结论。

### 随附说明的禁忌只按此工作流保存

来源将下列内容归于 `请避免 (1).txt`：除 IK 外避免 Path／Transform 等新约束；禁用 shear、Clipping、Two-Color Tint；尽量不 K Draw Order；文件路径及骨骼／插槽／附件／皮肤／动画名不使用中文；不要在同一 Slot 下多图切换（来源称会有游戏白字）。这些作为**本工具随附说明的使用限制／社区经验**保存，不升级为任意 DD 动画或所有转换器的普遍禁令；未有逐项复现记录时，不冠以本轮实测。

## 与龙骨文档交叉引用的纠错

这部分仅纠正文档主动引用上一份资料时的说法，不混同两种工具：

- “三个 GUI 构建”不准确：专题33所录仅 A 有 GUI，B／C 没有。
- 空 version 回填 `2.1.27` 属于上一份 A（常称v1.0.1），不是 B（常称v1.0.5）；回填空值也不是无条件写死所有版本。
- 上一份 B 的负整数防护是入口 `value < 0` 抛出 ValueError；本降级文档描述的是 `value and value != -1`。不能称两者实现相同，也不能据此替换本工具的实际代码说明。

这些对照仍以各文档的来源报告为依据，不是本轮重新解包核验。原始文档未被改写，疑点集中在本专题解释和来源账本，不污染另一工具的功能或版本记录。
