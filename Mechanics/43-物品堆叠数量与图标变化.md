## 用途与文件位置

若希望某个物品随着当前堆叠数量改变背包／物品栏图标，需要在 Mod 根目录建立：

```text
shared\inventory\<自定义前缀>.item.display.json
```

文件名也可以直接写成：

```text
shared\inventory\item.display.json
```

但不推荐使用无前缀文件名。它更容易与原版、DLC或其他 Mod 的同路径同名文件发生覆盖冲突。应优先使用当前 Mod 的唯一前缀，例如：

```text
shared\inventory\my_mod.item.display.json
```

`*.item.display.json` 属于 JSON 配置，必须保存为 **UTF-8 无 BOM**。

官方可见路径实例：

```text
DarkestDungeon\dlc\735730_color_of_madness\shared\inventory\com.item.display.json
```

该官方文件内容为空对象 `{}`，只能证明文件路径和加载类型存在，不能单独证明字段的完整语义。非空结构主要由 Mod「Stacking Item Icons」等 Workshop 实例补足。

## JSON 结构

一个文件可以同时定义多个物品。基本格式为：

```json
{
  "<物品type><物品id>": {
    "icon_thresholds": [ 1, 2 ],
    "can_unpack": true
  }
}
```

### 顶层键：`<type><id>` 直接拼接

顶层键由该物品在 `inventory_item:` 中的 `.type` 与 `.id` **直接拼接**而成，中间不添加 `+`、空格或其他分隔符。

例如物品定义为：

```darkest
inventory_item: .type "supply" .id "SF_Ele_healing_potion" .base_stack_limit 2
```

对应的显示配置键为：

```json
"supplySF_Ele_healing_potion"
```

其他实例：

| `.type` | `.id` | `item.display` 顶层键 |
|---|---|---|
| `supply` | `shovel` | `supplyshovel` |
| `gem` | `onyx` | `gemonyx` |
| `quest_item` | `antivenom` | `quest_itemantivenom` |
| `gold` | 空字符串 | `gold` |

这里的拼接规则与 PNG 文件名不同：顶层键不写 `+`，PNG 文件名必须写字面量加号 `+`。

## `icon_thresholds`

`icon_thresholds` 是按升序排列的堆叠数量阈值数组。数组顺序同时决定图像后缀的零基编号：

- 数组第 1 项对应 `_0.png`；
- 数组第 2 项对应 `_1.png`；
- 数组第 N 项对应 `_(N-1).png`。

已确认实例：

```json
{
  "supplySF_Ele_healing_potion": {
    "icon_thresholds": [ 1, 2 ],
    "can_unpack": true
  }
}
```

与以下两张图对应：

```text
inv_supply+SF_Ele_healing_potion_0.png
inv_supply+SF_Ele_healing_potion_1.png
```

其中 `_0` 图表现一瓶药，`_1` 图表现两瓶药；即堆叠数 1 使用 `_0`，堆叠数 2 使用 `_1`。

Workshop 实例还存在稀疏阈值，例如金币：

```json
"icon_thresholds": [ 50, 100, 200, 300, 400, 500 ]
```

并依次提供 `_0.png`、`_1.png`、`_2.png` 等同数量变体。结合这些实例，可把阈值理解为依次划分图标区间：每个数组项对应同下标图像。由于官方非空配置缺失，稀疏阈值在边界数值上究竟于“达到该值”还是“超过前一值”切换，当前资料没有独立实机测试结论。若设计要求每一个具体数量都严格对应一张图，最稳妥的写法是连续列出：

```json
"icon_thresholds": [ 1, 2, 3, 4 ]
```

并提供 `_0.png` 至 `_3.png`。无论使用连续还是稀疏阈值，都应让最后一个阈值覆盖设计允许的最大堆叠数量，避免依赖超过最后阈值时尚未确认的回退行为。

## `can_unpack`

`can_unpack` 是布尔值：

```json
"can_unpack": true
```

Workshop 实例中，可拆分的补给、宝石等通常写 `true`，金币写 `false`。因此该字段可按“该物品堆是否允许拆分／解包”理解；其所有具体鼠标操作和特殊物品交互边界尚无官方非空实例或专项测试，不应从该字段继续推导图标阈值之外的行为。制作普通可拆分补给时可参照同类物品写 `true`；不可拆分类型应参照同类实例写 `false`。

## 图像位置

阈值图像放在 Mod 根目录下：

```text
panels\icons_equip\<物品type>
```

例如 `.type "supply"` 的物品放在：

```text
panels\icons_equip\supply
```

`.type "gem"` 的物品放在：

```text
panels\icons_equip\gem
```

文件夹名保留 `.type` 的原始字符串；例如 `quest_item` 使用：

```text
panels\icons_equip\quest_item
```

## 图像命名格式

普通物品图标的基础命名规律为：

```text
inv_<type>+<id>.png
```

堆叠数量变体在 `<id>` 后增加下划线和零基序号：

```text
inv_<type>+<id>_<零基序号>.png
```

例如：

```text
panels\icons_equip\supply\inv_supply+SF_Ele_healing_potion_0.png
panels\icons_equip\supply\inv_supply+SF_Ele_healing_potion_1.png
```

注意：

1. `inv_` 是固定前缀。
2. `<type>` 与 `<id>` 之间的 `+` 是文件名的一部分，不能省略。
3. `<type>`、`<id>` 必须与 `inventory_item:` 定义一致。
4. 变体编号从 `0` 开始，不是从 `1` 开始。
5. 若 `.id` 为空字符串，仍保留 `+`。金币实例为：

```text
panels\icons_equip\gold\inv_gold+_0.png
```

6. `icon_thresholds` 有 N 项时，应完整提供 `_0.png` 至 `_(N-1).png`，避免阈值命中时缺图。
7. 文件扩展名使用 `.png`。

## 图像规格

当前检查的 Mod「Stacking Item Icons」653 张阈值图像，以及本地职业实例的两张药水阈值图，画布均为：

```text
72 × 144 像素
```

因此为物品栏图标制作堆叠变体时，应使用 `72×144` 的透明 PNG 画布，并参照同类原版图标安排实际图案的位置与留白。现有资料只能把 `72×144` 确认为原版／主流 Mod 遵循的标准规格，尚不能单凭静态文件证明其他尺寸一定无法加载；创作时不要无故偏离该规格。

## 完整示例

```json
{
  "supplyexample_potion": {
    "icon_thresholds": [ 1, 2, 3 ],
    "can_unpack": true
  }
}
```

需要同时提供：

```text
panels\icons_equip\supply\inv_supply+example_potion_0.png
panels\icons_equip\supply\inv_supply+example_potion_1.png
panels\icons_equip\supply\inv_supply+example_potion_2.png
```

## 来源实例

- 官方 DLC 空配置：`DarkestDungeon\dlc\735730_color_of_madness\shared\inventory\com.item.display.json`。
- Workshop 优先实例：`Mod「Stacking Item Icons」\shared\inventory\gold.item.display.json`、`gems.item.display.json`、`supplies.item.display.json`。
- Workshop 图像实例：`Mod「Stacking Item Icons」\panels\icons_equip\supply\inv_supply+shovel_0.png` 等。
- 自定义物品补充实例：`Mod「至古者的选民」\shared\inventory\SF_Ele.item.display.json` 与对应药水图像。

## Agent 生成前检查

1. 文件是否位于 `shared\inventory\`，且使用低冲突的 Mod 自有前缀？
2. 顶层键是否严格等于 `.type` 与 `.id` 的直接拼接，没有错误加入 `+`？
3. PNG 文件名中是否正确加入了 `+`？
4. 阈值数组是否升序，变体编号是否从 `_0` 开始？
5. N 个阈值是否提供了 N 张 `_0` 至 `_(N-1)` 图像？
6. 图像是否位于 `panels\icons_equip\<type>\`？
7. 图像是否采用标准 `72×144` 透明 PNG 画布？
8. JSON 是否为 UTF-8 无 BOM？
