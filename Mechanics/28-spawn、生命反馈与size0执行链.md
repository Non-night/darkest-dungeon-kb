## 英雄战斗开始时切模式的崩溃边界

### 当前结论：先打通临时通路，再由战斗开始附魔直接切模式

知识库编写者于2026-11-08补充实测：在**模式的战斗开始时效果**中执行召唤、由所召唤 size-0 按既有要求在自身 Spawn 中自加行动点、触发自身生命反馈并引出 Effect 的流程，会打通一个底层原因未知的通路。生命反馈只需实际引出 Effect，其具体输出无关紧要，**不要求这条生命反馈 Effect 本身负责切模式**。

仅当该通路已打通，战斗开始时附魔（Buff 的 `combat_start_additional_effect_ids`）才可以直接引出切模式 Effect，无需让它自己的切模式动作再次经过 size-0 生命反馈；若通路未打通，无论在战斗开始时附魔中采用何种写法，都会在战斗开始时崩溃。“通路”只是对实测现象的描述，不代表已经确定底层引擎机制。

通路从打通起持续到**存档重启**；存档重启后必须重新执行前置流程。生命周期的界限不是“游戏程序重启”，不得混淆。不能依赖此前某场战斗已打通，也不能据此假定该状态可跨存档重启留存。所有战斗开始时有可能切模式的模式，都必须在各自的模式战斗开始效果里带上该流程，不能只给某个初始模式配置。

前置流程的加动条件不变：必须由触发生命反馈的 size-0 在自身 Spawn 中通过 Effect 自加行动点；不能用召唤参数附带行动点、Info 天然回合等替代，不能写 `.bonus_action_next_turn true`；`.summon_does_roll_initiatives 1` 配合天然回合也不是替代方案。下方保留这些既有细节。

推荐直接在模式战斗开始效果引出的既有召唤／加动／生命反馈流程中完成切模式，把条件控制交给其他地方。改用战斗开始附魔并不能省掉打通通路的前置流程，不能据此作为简化方案。本次只明确了战斗开始附魔的直接切模式条件，不自动把模式自身直接切模式、饰品独立 Trigger 或其他历史失败路径全部改判为可直接切换。

本条修正2026-11-05旧说法：不能再绝对要求每次战斗开始附魔切模式都由其自身 size-0 生命反馈执行；需要区分“打通通路”和“随后直接切模式”两件事。来源：`Sources/combat_start_mode_switch_path_20261108.json`；知识库编写者实测报告，Agent未自行游戏测试。

### 历史观察与既有生命反馈切模式流程

以下2026-10-07、2026-11-05记录保留为历史条件与既有实现。未区分通路状态的失败记录，不得覆盖上方最新的条件化结论。

当前用户于 2026-10-07 补充：在英雄的模式定义中，战斗开始时效果直接对该英雄切换模式会导致游戏崩溃。当前已知的不可用范围还包括：

- 战斗开始时 Trigger 直接召唤的 size-0，在其 `spawn` 中直接对该英雄或整个英雄侧切模式；
- 战斗开始时 Trigger 召唤的 size-0 再召唤的 size-0 所执行的切模式；
- 上述后续 size-0 的死亡反馈中执行切模式；
- 上述后续 size-0 的死亡变身过程中执行切模式；
- 以及目前已知的同类“战斗开始 Trigger 召唤链中，试图直接对英雄产生有效模式切换”的路径。

这些路径均应按崩溃风险处理，不要因为切模式被放在更深的 spawn、hp_reaction、death_reaction 或死亡变身中，就认为它脱离了战斗开始时序风险。这里的“已知范围”不是对所有可能调用链的底层穷举；未测试的新路径仍不能默认安全。

### 既有的英雄侧生命反馈切模式流程

原有可行方案把前置流程和实际切模式都放在以下执行链中；仍可使用，但不再代表通路打通后战斗开始附魔的唯一执行路径：

1. 战斗开始 Trigger 先引出 size-0 召唤链；
2. 让**实际负责触发生命反馈并执行模式切换的那个 size-0**持有一个行动点。该单位可以是战斗开始 Trigger 直接召唤的 size-0，也可以是它后续再召唤的 size-0；不要求一定由战斗开始 Trigger 直接召唤的第一台 size-0 持有行动点；
3. 该行动点必须在这台 size-0 自身的 `Spawn` 中，通过 Effect 给自己增加。不能改用召唤时附带行动点、Info 中的天然回合或其他行动点来源；
4. 给自己加行动点的 Effect 不能写 `.bonus_action_next_turn true`，当前用户确认该写法在此路径中必定崩溃；
5. 不能让这台 size-0 依赖天然回合来执行迂回。无论 Info 中 `.number_of_turns_per_round` 写为 `1` 还是大于 `1`，再配合召唤 Effect 的 `.summon_does_roll_initiatives 1`，都属于已知必定崩溃的路径；该字段是数字布尔，只应写 `0` 或 `1`，不能写 `true`。即使写 `1` 在语法上属于数字布尔，也不能用于本迂回；
6. 由该持有行动点的 size-0 触发自身的生命反馈；
7. 若在此既有链内完成切模式，在这台 size-0 的生命反馈内执行；若只为打通通路，生命反馈实际引出 Effect 即可，输出无关紧要，随后战斗开始附魔可直接切模式；
8. 因为生命反馈内无法定向，切模式必须使用 `.target target_enemy_group` 指向英雄全体。

多数 Mod 角色的模式 ID 是独一无二的，因此这种对英雄侧使用 `target_enemy_group` 的写法通常可以按唯一模式 ID筛选目标；但仍须检查模式 ID 是否与其他英雄或怪物冲突，不能把“多数情况下独一无二”写成全局保证。

这里“持有行动点”是对执行该次 hp_reaction、打通通路的 size-0 的严格实现条件：行动点必须由该单位在自身 Spawn 中自加，而不是由战斗开始召唤参数、天然回合或下一回合奖励行动提供。不能跳过前置流程，或仅凭把切模式搬进 spawn、死亡反馈、死亡变身就视为等价；通路已打通后战斗开始附魔直接切模式是上方明确记录的条件化例外。

## AWR 召唤与受击接口的历史边界

迂回表第136条记录了以下历史观察：在普通攻击技能或技能驱动的攻击类 Trigger 中，召唤 Effect 写为 `.queue false .apply_with_result true` 时，被召唤单位的 spawn Effect 继承该召唤时序；若 spawn 对目标施加 `damage_received_percent` 易伤，则该易伤可以参与本次直伤。这里“干预本次直伤”的实测范围特指目标易伤路径，不把 AWR 召唤或 spawn 的时序继承推广为任意属性都能回溯修改直伤。

同一原表测试还记录，受击侧的 `hp_reaction` 生命反馈和饰品受击 Trigger 无法用这一路径提前干预已经结算的直伤。P2088–P2089 关于“受击 Trigger／生命反馈发生得太晚”的原因解释属于原表推测，不升级为已确认的引擎内部机制。以上是原表历史观察，未注明适用版本；当前版本仍应结合新版时序变化重新核对。

## spawn Effect 的严格顺序
同一怪物 Info 中的 `spawn: .effects` 按**从上到下**执行；同一 `.effects` 内存在多个 ID 时按**从左到右**执行。

- 前一个 spawn Effect 结算完成后才进入后一个。
- spawn Effect 中的 `.queue`、`.apply_with_result` 等技能时序字段疑似没有独立意义；当前不能用它们改变上述列表顺序。
- 未发生中途变身时，spawn 或生命反馈带出的 Effect 写在哪个单位的 Info 中，该单位就是施术者。spawn 内 set 的列表来源与当前形态归属须按本页“size-0 的 spawn 内连续 set 变身”区分。
- spawn Effect 可以插入召唤者技能 Effect 的结算中。

## size-0 的 spawn 内连续 set 变身（黑圣物多段式）

**知识库编写者补充（2026-09-19，行为结论）**：在最初的 size-0 A 的 `spawn: .effects` 中，按“内容1 → `.set_monster_class_id` 变成 size-0 B → 内容2”排列，set 到 B 不会启动 B 自己的 spawn 列表，也不会把 A 的列表从头再执行。继续的是 A 已开始的 spawn 剩余列表；变身后剩余的自身操作由当前形态 B 承接。

**spawn 列表来源与生命反馈定义必须分开**：变身完成后，生命反馈使用 B 自身的 `hp_reaction`，不继续使用 A 的生命反馈定义。后续生命变化是否实际触发 B 的某条反馈，仍须满足该条反馈的阈值、方向与书写顺序条件；“使用 B 的定义”不等于“B 的反馈无条件触发”。参见 [hp_reaction / 生命反馈](08-hp_reaction.md)。

### A → B 的逐步示意

以下是行为时序示意，不是可直接放入游戏的完整配置；腐蚀和流血指状态施加，不代表立刻结算 DOT 伤害。

| 定义所在形态 | 定义的行为 |
|---|---|
| A 的 spawn | 给自身挂腐蚀 → set 变为 B → 给自身挂流血 |
| B 的 spawn | 治疗英雄全体 |
| A / B 的 hp_reaction | 各自具有自身的生命反馈定义 |

在知识库编写者所描述的、腐蚀得到保留的配置下，召唤 A 的过程为：

1. A 入场并启动 A 的 spawn。
2. A 给自身挂腐蚀。
3. A set 成 B；该示例中 B 仍带腐蚀。
4. 继续 A 的 spawn 剩余项，由 B 给自身挂流血。
5. A 的这条 spawn 列表执行完毕。B 的 spawn 未启动，因此其中“治疗英雄全体”不执行。

若变身完成后又发生能触发生命反馈的生命变化，检查 B 的 hp_reaction；不能因剩余 spawn 来自 A 而回查 A 的 hp_reaction。此示例只有 A→B 一次 set；同一个对象进一步连续 set 时，还必须检查下列限制。

### “set 变身”的术语边界

当前用户于 2026-10-01 补充：知识库中“set 变身”专指 `.set_monster_class_id` 或 `.set_monster_class_ids` 所执行的怪物大类变换；它与 `.set_mode` 完全无关。`.set_mode` 只能称为模式切换，不得套用“set 变身”的生命继承、`reset_hp`、死亡门或变身时序结论。

### 继承配置与未知边界

生命与 Buff 的继承/重置由 set 配置决定，不能由“继续 A 的 spawn”推出无条件保留。现有精确字段入口为 [set_monster_class_reset_hp](../Effect/keyword/Effect.set_monster_class_reset_hp.md)、[set_monster_class_reset_buffs](../Effect/keyword/Effect.set_monster_class_reset_buffs.md)，另有 [set_monster_class_carry_over_hp_min_percent](../Effect/keyword/Effect.set_monster_class_carry_over_hp_min_percent.md) 规定继承生命的最低百分比。

当前用户于 2026-09-30 补充：`.set_monster_class_reset_hp` 的省略默认值为 `false`；省略／`false`／`0` 时继承原血量，写 `true` 或 `1` 时重置为满血。对死而不僵目标，默认血量继承也会继承其死而不僵状态；显式开启 HP 重置则使其成为满血正常状态。对继承了死而不僵状态的 set 目标，后续治疗不能解除该状态；本节早期的“尚未知”表述由下文知识库编写者明确补充取代。此补充不改变其他 set 配置边界：不补造 set 的生命换算公式，也不把“示例中的腐蚀保留”外推为任意 DOT/任意配置均保留，或认定某个 reset_buffs 值已证明控制全部 DOT。

尚未确认：set 本身发生生命重置/继承时是否触发 hp_reaction、该瞬间的精确检查时点，以及已经进入执行的旧 hp_reaction 内再变身的重入细节。本次结论限定为 size-0 的 spawn 内 set，不外推到死亡变身、shifter 或所有变身调用来源。

### 连续 set 的既有问题

社区资料《暗黑地牢迂回代码整理2026-08-04-1833.docx》已有以下连续 set 边界；“黑圣物多段式”在这里是写法别名与案例检索词，不是独立 Mod 专题或官方引擎规范。

- **从第二次 set 起的同侧异常**：同一怪物连续 set 时，从第二次 set 开始，spawn 中原本对英雄跨侧的 Buff 施加会异常按同侧处理，减益施加率和目标减益抗性不再参与该 Buff 概率计算。因此不能依赖跨侧减益筛选构造这条连续 set 链的条件门；不能把此异常泛化到流血、腐蚀、位移等全部独立抗性系统。
- **spawn 定向失效**：资料另记同一怪物连续多次 set 后，spawn 不能再按特定职业/base class ID 定向到英雄或怪物。该条未单独给出首个失效 set 的精确序号；不要把前条“从第二次”擅自套入这条。需要定向的设计不得直接沿用普通 spawn 定向规则。
- **另召唤新对象与原地变身不同**：资料记载输出端另召唤的新 size-0 仍可使用 spawn 定向。这不是目的地 B 的 spawn 被启动；这是新召唤物独立入场。实际来源、目标、时序及自灭兜底仍须逐项核对。
- **自身 FX 限制仍在**：涉及死亡变身或 set 变身技能时，继续遵守 [变身技能自身 FX 限制](81-死亡变身与set变身技能的自身FX限制.md)；此规则不等于所有动画均被禁止，也不证明任意连续 set 链安全。

### 连续 set 后 monster_type_count_min 检测例外

**知识库编写者补充（2026-09-19）**：对连续 set 变身后的 size-0，绝大多数情况下 `monster_type_count_min` 无法正常检测。黑圣物中存在采用该 Rule 且生效的案例，但其他人无法复刻；保留这一有效个例，不写成“所有情况下绝对失效”，也不据此提供普遍可靠的实现保证。

这里说的是**被计数对象经过连续 set** 的特殊情况，不是重新定义 Rule 持有者属于哪一侧。普通情况下该 Rule 会统计仍在场的对应类型 size-0，包括死而不僵者；这条普通结论不能覆盖连续 set 的检测异常，亦不能将二者混为“所有 size-0 都不被统计”。

设计上不得把该 Rule 作为连续 set 后 size-0 的可靠存在检测或数量条件。当前没有确认异常的精确 set 次数、成功个例所需配置、返回值究竟是 false/null/数量偏差，以及原因是否涉及类型刷新；不将任一解释写成引擎事实，也不假定 is_false_rule 取反即可修复。案例仅由知识库编写者转述，本次没有扫描黑圣物文件验证其配置。

### 死亡后的召唤与 set 阻断也适用于生命反馈

****当前用户于 2026-09-30 补充并于 2026-10-01 扩展**：所有 Effect 都受死而不僵目标门限制，不仅是召唤或 set。没有同时显式写 `.can_apply_on_death true .can_apply_on_corpse true` 时，只要 `.target` 所映射的最终检查单位处于死而不僵，Effect 就不生效。写有 `.swap_source_and_target true` 时，原目标交换后成为施术者，故需检查该实际施术者是否死而不僵；判定单位仍由 `.target` 映射决定。任何 Effect 同时显式写出两个 true 后，都可正常作用于死而不僵单位。少写任一项不行；依赖默认值不算显式放行。狗贼二段式的二号机召唤须保留门控，详见下文专节。

set 变身获准作用于死而不僵目标后，结果还取决于 `.set_monster_class_reset_hp`：该字段默认值为 `false`。省略该字段或明确写 `false`/`0` 时，set 默认继承原血量，因此也会继承死而不僵状态；若 set 同时写 `.set_monster_class_reset_hp true` 或 `.set_monster_class_reset_hp 1`，则变为满血正常状态并脱离死而不僵。当前用户于 2026-09-30 补充：对继承了死而不僵状态的 set 目标，后续治疗不能使其脱离死而不僵；不要把治疗当作复活或解除该状态的办法。

因此，“死后普通 spawn 后续项仍执行”或“生命反馈仍能进入并执行普通 Effect”本身不决定召唤／set 成败；需分别检查目标死亡状态、两个显式放行字段，以及 set 的 HP 重置选项。未因该结论补造死亡后所有 hp_reaction 是否继续触发的统一规则，也不把 set 阻断外推到 death class 死亡变身。

## AOE 同层切模式截断与即时修正失效

`.set_mode` 执行后，`skill_instant` 提供的修正增减益不再生效。这是修正生效状态的边界，不能直接解释为所有来源的 Buff 实体均被删除，也不据此补造任意来源覆盖后的具体生命周期。

在 AOE 多目标技能中，同一时序层执行 `.set_mode` 后，会截断该层后续目标的单体 Effect。原表例子为攻击1234全体、以 `.target target` 对每个目标分别施加流血，同时在同层切换模式，结果只有首个目标承受流血。该问题不要求技能包含多个模式切换，不能因只有一个 `.set_mode` 就排除它；“单体 Effect”是每次针对当前单个目标的调用，不等于技能本身是单体技能。

处理时，应将需要覆盖全部目标的效果放在较早时序层，将切模式放在较晚层；原表示例为前者使用 `queue false`，`.set_mode` 使用 `queue true`。依据是 AOE 先完成所有目标的 `queue false`，再处理所有目标的 `queue true`，而不是先完成首个目标的全部时序再进入第二个目标；同层切模式会中断本层后续目标。不能只调整引用列表的文本顺序来替代分层。普通分层顺序见 [queue 与 AWR](04-queue与AWR.md)。

该分层方案只覆盖上述调用条件，不能保证含其他模式切换、饰品 Trigger、附魔或独立执行链的复杂组合一概安全；此类额外切换仍按下节核对。这里的 `.set_mode` 只指模式切换，不是 `.set_monster_class_id`／`.set_monster_class_ids` 的 set 变身。

证据：迂回表第45条 P1086/X1262–P1090/X1266；原表将分层规避方法归于欠月狼。当前用户于2026-11-03确认按上述完整边界补入，非本轮新增实机测试；不把原表的流程解释冒称为引擎源码验证。

## 同一技能多个切模式的时序截断风险

当前用户补充（2026-09-25）：如果一个技能包含多个切模式，可能发生相互的时序截断干扰。审查这类技能时，不能只按 `.set_mode` 的书写顺序假定每次模式切换都能完整执行；必须把各次切模式所在的调用层、同一技能内其他 Effect、模式切换对技能状态/技能 Rule 的清理或截断影响，以及后续模式切换是否会截断前一次切换后的剩余流程一起核对；还必须把饰品 Trigger 和附魔追加 Effect 插入同一调用链后造成的额外模式切换、状态清理、时序竞争和截断影响纳入检查。

该结论记录为风险边界而非“多个 `.set_mode` 必定失败”：只有在具体技能包含多个切模式时才触发专项检查。若后续 Effect、技能 Rule、按键记忆或模式相关状态依赖前一次切换完成，不能仅凭文本相邻或数组顺序证明依赖成立；应拆分时序、减少同一技能内的连续切模式，或采用已确认的独立调用链，并逐项检查实际生效与清理结果。

## size-0 通过对侧群体切换模式

当 size-0 只是承担条件载体，需要把对侧英雄或怪物切换到一个明确的模式时，通常不需要 spawn 定向。若设计目标就是对侧全体，可以让 `.set_mode <mode_id>` 配合非指向性的 `.target target_enemy_group`：对侧拥有该精确模式定义的单位才会受到模式切换，没有对应模式定义的单位无事发生；怪物侧同理。

```darkest
// 仅示意目标映射；mode_id 必须替换为当前 Mod 的唯一模式 ID
effect: .name "SZ0_SWITCH_UNIQUE_MODE" .target target_enemy_group .set_mode sz0_unique_mode
```

这不是按职业或 base class 的 spawn 定向，也不表示 `target_enemy_group` 会读取某个站位。它会把 Effect 的最终范围扩大到对侧全体，因此只有在设计明确允许对侧所有同 ID 模式单位被处理时才适用。模式 ID 若过于简单或常见（例如原版已有的 `beast`，或其他普通单词），其他拥有同名模式定义的单位也可能被一起切换；应改用带 Mod 前缀且唯一的模式 ID，并在风险说明中明确这一碰撞边界。不要因为多数模式名不重复，就把这种写法当成无条件安全的精确筛选。

## 生命反馈插入
生命值发生变化时，`hp_reaction` 立即检查并立即执行。它可以插入 spawn 列表中间：

```text
spawn Effect A
生命变化
hp_reaction Effect
返回原 spawn 列表
spawn Effect B
```

阈值为闭区间：

- `.is_under true`：生命比例小于等于阈值。
- `.is_under false`：生命比例大于等于阈值。

## 多阈值与多段生命变化
- 一次独立生命值变动跨越多个 `hp_reaction` 阈值时，按 Info 中生命反馈代码自上而下的书写顺序检查，触发第一条同时符合本次阈值跨越范围和方向的 reaction；不按阈值数值的最近、最高或最低选择。
- 一次独立生命值变动只按上述顺序选择一条 reaction；多个 Effect 造成的多段真伤即使都在同一个 `queue` 时序内，也属于多次独立生命值变动，每一段都可以分别触发一次生命反馈。
- 完整的阈值闭区间、`is_under` 方向和重启误触发边界见：[hp_reaction / 生命反馈](08-hp_reaction.md)。

## size-0 死亡与“死而不僵”：spawn调用继续，目标死亡门及双字段例外
- size-0 在 spawn 列表中死亡后，后续普通 Effect 仍会继续**被调用**；死亡不会把后续列表项整体跳过。
- 例如 `a → b → c` 中，`a` 自灭，`b` 尝试对死而不僵目标召唤或执行 set，`c` 对英雄全体治疗：`a` 调用并使单位死亡；`b` 仍被调用；若目标死而不僵且未同时显式写两个死亡放行字段，召唤/set无法有效生效；`c` 仍被调用，并可正常执行普通治疗。
- 因此“spawn 不会因死亡/set 变身而被阻断”描述的是调用链继续，不是保证所有 Effect 都成功。召唤与 set 默认受目标死亡门阻断，但同时显式写两个放行字段可突破；不能把 `b` 的无效结果写成“b 没有被调用”。
- 该死亡门同样覆盖 `hp_reaction` 所带出的召唤和 set；生命反馈可以继续作为调用来源，但目标处于死而不僵时，只有相关 Effect 显式同时写两个放行字段才可突破。
- 在常规结束回合技能中，如果中途召唤并击杀 size-0，它可能进入“死而不僵”状态：该单位的状态已经是死亡，但实体仍留在场上，也仍能继续执行自身后续的 spawn Effect。
- 死而不僵的 size-0 会在其召唤者的个人回合结束后彻底消失；无论召唤者是正常结束回合，还是以其他方式错误／非正常结束回合，均会触发这一最终清除点。
- size-0 在存活和死而不僵两种状态下都会保留互动碰撞箱，可能遮挡画面上“相同”位置的怪物，使鼠标无法选择该怪物。这里的重叠位置不是普通站位意义上的完全相同，不能通过 `in_rank` Rule 检测；具体坐标关系尚未解释。手柄仍可选择被遮挡怪物，但会缺失选中 UI 高亮、悬停简介等表现。
- **普通情况下，`monster_type_count_min` 会计算仍在场、类型匹配的怪物，明确包括处于死而不僵状态的怪物和死而不僵的 Size 0。** “已死亡”不等于“已离场”；只要实体仍在场且类型匹配，就会参与计数。连续 set 后的 size-0 属于本页所述的检测例外：绝大多数情况下无法正常检测，不能仅凭仍在场就保证计数有效。
- 群体 `.target` 类型（如 `performer_group`、`target_group`）中的死而不僵门仍按每个最终目标独立检查；其中一个目标处于死而不僵，不会使同一群体中的其他目标一并失效。
- 死亡门适用于所有 Effect，而不只召唤与 set：若没有同时显式写 `.can_apply_on_death true .can_apply_on_corpse true`，当 `.target` 对应的最终检查单位处于死而不僵时，Effect 不生效。若写了 `.swap_source_and_target true`，原 `.target` 对应单位在交换后成为实际施术者，因此检查的是它是否死而不僵；本质仍按 `.target` 所映射的单位判断。显式同时写出两个 true 后，所有 Effect 均可正常生效于该死而不僵单位。
- 群体目标（如 `performer_group`、`target_group`）中的每个最终目标独立执行检查；一个目标失效不会连带同群体其他目标。反向 Effect 也按每个最终目标／交换后的实际施术者独立检查。
- 此为当前用户提供的黑盒规则。狗贼二段式为特例：二号机召唤须保留死亡门。

## 尸体仍是特殊怪物实体
游戏中的尸体并不是脱离怪物系统的普通尸体对象，其本质是性质特殊、怪物类型为 `corpse` 的怪物实体。因此分析怪物类型、目标、Effect 延续或计数规则时，应按特殊怪物处理；不得仅凭日常语义把尸体排除在“怪物”之外。

## `.summon_ranks 0`
`.summon_ranks 0` 等效于 `.summon_ranks 1`，即按一号位处理。size-0 模板常使用 `0`，但这不代表存在常规“零号站位”。

## 狗贼二段式：二号机召唤必须保留死亡门

### 与“局师傅三段式”老方案的关系

迂回表第73条 P1261–P1283/X1482–X1507 描述的“局师傅三段式”是**历史机制方案**，原段为原理说明，不是本次复查重新执行的实机测试。其完整链条是：

1. 英雄或怪物本体召唤 Size-0 A；A 在自己的 `spawn` 中先召唤 Size-0 B。原表按嵌套执行理解：B 的入场与内部 `spawn` 处理结束后，A 才继续自己列表中的下一步；不得把 A 后面的“检测 B”提前到 B 完成自身处理之前。
2. 在原表的配置中，以受控传递方式给 B 最大生命减益，使 B 分为最大生命为 0 与非 0 两种情况。怪物侧降低最大生命后，当前生命通常不会立即同步降低；B 再自疗，使当前生命向新的最大生命复位。原表记载零上限分支由此自然死亡，非零分支存活。原表提到的“通过 spawn 定向偷取”只是一种历史输入手段；偷取可能误伤别的 Buff，只有严格受控环境才可自由使用，不作默认方案。最大生命与当前生命的对象差异见[最大生命值变化边界](53-最大生命值变化、当前生命与死门边界.md)。
3. A 随后以 B 为目标尝试召唤 Size-0 C。该老方案依赖普通死亡目标门：B 已死亡时 C 不出现，B 仍存活时 C 出现；若给召唤 Effect 同时显式写 `.can_apply_on_death true .can_apply_on_corpse true`，会突破用作分支的死亡门，不能照搬。B 死而不僵仍可能保留模型、站位和碰撞区域；死亡不等于 A 的后续 spawn 列表未被调用。
4. C 出现与否就是条件结果；出现时只能执行 C 的 `spawn` 在该调用方、最终目标和时序下可正常生效的 Effect。原表安排 A 收尾清理 A/B，C 完成输出后自灭。C 的 spawn 若要精确作用于一个完全未知的随机英雄，并没有由这套方案自动解决；已知 ID 可另核 spawn 定向。清理、目标和死亡门都必须逐项检查。

输入端是 Buff 条件、输出端是 C 是否出现及其 Effect，不是“任意 Effect 无条件可执行”的保证。迂回表后续第74条 P1288–P1301/X1514–X1531 说明，B 自己死亡后的普通 spawn Effect 仍可继续被调用，但死亡能阻断后续以 B 为检查目标的召唤；因此可省去 A，让 B 在自己的 spawn 中读取条件并尝试召唤 C。**当前用户于 2026-11-03 明确更正：三段式与狗贼二段式在该条件输入／输出用途上没有实质区别；凡原本使用三段式之处，都可直接使用更省 Size-0 的二段式以提高效率。** 三段式只保留用于解释原表老方案，不作为现行优先实现。二段式也须遵守下述死亡门与来源、目标、清理边界。

当前用户于 2026-09-30 补充：狗贼二段式使用 size-0 一号机的死亡状态，作为二号机召唤是否成功的判别条件。由于任意 Effect 同时显式写 `.can_apply_on_death true .can_apply_on_corpse true` 都可作用于死而不僵目标，二号机的召唤 Effect 必须让常规目标死亡门保持有效：`.can_apply_on_death` 与 `.can_apply_on_corpse` 两项都不写，或两项都显式写 `false`；不要将两项同时设为 `true`，否则二号机召唤会绕过本来用作分支信号的一号机死亡状态，破坏判别逻辑。

### 前置死亡方式与后续 spawn

迂回表第74条 P1288–P1300/X1514–X1529 记录的历史机制观察：Size-0 可由天生零血且未设置零血不死、指向自身的 `.kill 1`、指向自身且匹配其实际 `enemy_type` 的 `.kill_enemy_types`、确实足以致死的极大真伤，或最大生命归零后自疗以刷新当前生命至零等方式先行死亡。这些途径都**不终止后续普通 `spawn` Effect 的调用**；但若后续 Effect 以已死的自身为死亡门检查目标而尝试召唤，且没有同时启用 `.can_apply_on_death true` 与 `.can_apply_on_corpse true`，召唤不能生效。不能把“后续被调用”误读成“后续召唤成功”，也不能把“死亡阻断该召唤”推广到全部非召唤 Effect。

原表指出极大真伤可能受外部硬减干扰，因而是有条件的致死手段，相对不推荐；`.kill 1` 也不因此成为普通善后自灭的默认选择。当前用户于 2026-11-03 补充：在上述途径的比较中，`.kill_enemy_types` 结算最快，降低最大生命值再治疗最慢。这是相对速度经验，不提供通用耗时或所有调用环境的精确排序；`.kill_enemy_types` 仍须核对最终目标及实际 `enemy_type`。

这是狗贼二段式的特定设计约束，不是对所有召唤的通用建议。一般需要对死而不僵目标召唤时，双字段显式 `true` 仍可突破默认阻断；只有该二段式需要“死则不召”的分支时才必须保留阻断。

## 生命反馈二段式
生命反馈二段式通过 size-0 的生命值比例传递条件结果。典型构造包含：

1. 首次极大幅度提高 size-0 最大生命值。
2. 使用治疗、伤害、所受伤害修正或施术者反向 Effect，把条件真假编码成不同生命比例。
3. 由第一组 `hp_reaction` 分流，并触发后续 size-0 或目标 Effect。
4. 再次扩展最大生命值，配合前置无意义 reaction，避免存档重启时错误触发真正逻辑。

### 与生死门分支的历史方案取舍

迂回表第75条 P1309–P1313/X1544–X1552 将两种条件分支作历史方案对照：狗贼二段式以输入 Buff 决定 Size-0 的生死，再由死亡目标门决定下一台是否召唤；黑圣物的生命比例方案则以输入 Buff 改变 Size-0 的当前生命／最大生命比例，由怪物侧 `hp_reaction: .hp_ratio` 判定区间并决定后续召唤。原表认为前者的生死分支相对更抗干扰，后者的比例阈值相对更易受血量、最大生命及修正项影响；这只是两种方案的相对取舍，不是无条件可靠性排序。

比例方案的载体若仍存活，并且能在受控条件下清理本次输入 Buff、治疗到下一次判断所需生命状态，原表用连续 `set` 变身让同一对象参与多次分支，从而减少中间 Size-0 数量。原表使用真驱散清理属于历史实现背景；现行设计应优先按 Buff ID 定向驱散，不能将来源真驱散、偷取或任意治疗当作安全的通用复位。再次判断前还须核对当前形态的 `hp_reaction`、HP 继承／重置、阈值、残留 Buff、召唤目标与清理；连续 `set` 的 spawn 定向失效和同侧异常仍按本页专节处理。这不是本次新增实机测试，也不保证任意连续变身链可反复安全使用。

### 首次最大生命扩展的原因
最高难度“血月/狱火”存在全局规则，使所有怪物最大生命增加 `20%`。这是能够影响 spawn 中立即自灭 size-0 数值的少数全局修正；普通火炬 Buff 等通常来不及影响这种中间单位。

新版 `.ignore_hp_scale true` 可忽略此难度加血；所有生命反馈size-0均须设置，不再强制用极小HP与极大倍率稀释。

### 第二次最大生命扩展和重启保护

知识库编写者2026-11-05确认新版流程：所有生命反馈size-0加 `.ignore_hp_scale true`；可50当前/最大生命启动，扩展最大HP到100而不回血，进入后续流程。旧1→100000→回满→200000仅为历史兼容方案，不再必需。

- `.ignore_hp_scale true`排除难度生命缩放，不等于屏蔽其他最大HP Buff。
- 50当前HP、100最大HP使起点为50%；0.99向下/0.01向上空Effect sentinel继续防止重启误入真实反馈。

向下生命反馈必须把 `.hp_ratio 0.99 .is_under true` 的无影响 reaction 放在所有真实向下 reaction 之前；向上生命反馈必须把 `.hp_ratio 0.01 .is_under false` 的无影响 reaction 放在所有真实向上 reaction 之前。两个方向都使用时，两条 sentinel 都要存在。`0.999`、`0.9999` 或同类更高保护阈值可以按同一逻辑使用，但不能改变“先 sentinel、后真实 reaction”的顺序。`.tag 0` 可作为已收录的占位方案，但可能产生红字；无影响不等于无诊断输出。

## 反击与饰品被命中 Trigger 风险
反击和饰品的被命中 Trigger 中，size-0 与 `.health_damage` 组合可能导致游戏崩溃。需要在这些调用环境中驱动生命反馈时，优先使用治疗造成生命变化，不使用真伤触发。
