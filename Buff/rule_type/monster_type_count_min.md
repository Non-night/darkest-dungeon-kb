monster_type_count_min
# 分类
通用型（条件型）
# 参数类型
`rule_type` 固定字符串；配套 `rule_data.float` 为数值，`rule_data.string` 为字符串。
# 参数约束
- rule_data.float 写 0 时 rule 永远不会返回 true；安全创作必须填写 float >= 1。英雄侧数量1、空类型字符串并取反的战斗内条件组合已确认；其他取反情形的完整引擎边界仍未全部确认。
- `is_false_rule: true` 只在有效判定范围内翻转普通 `true`／`false`；范围外的 `null` 不会被翻转为 `true`。
# 固定值 / 参数候选
- float 示例：`value`
- string 示例：`monster type`
# 语义
- 例子：血裔的镜子
  这个是场上有血裔时携带者+4速的buff
  {
   "id" : "cc_trinket_speed_vs_vamps",
   "stat_type" : "combat_stat_add",
   "stat_sub_type" : "speed_rating",
   "amount" : 4,
   "remove_if_not_active" : false,
   "rule_type" : "monster_type_count_min",
  "is_false_rule" : false,
  "rule_data" : {
  "float" : 1,         这里写怪物的最少个数（别写0，写0这辈子都不生效）
  "string" : "vampire" 这里写怪物类型
   }
   },
- 指定 Rule 的读档／重启移除：`monster_type_count_min` Buff 写 `remove_if_not_active: true` 时，读档会使其消失，即使场上仍满足条件；原表也明确类比 `has_quirk` 配置该字段为 `true` 时的重启消失现象。用于两 Buff 抵消时，若抵消项消失而 `always` 项保留，组合净效果会被破坏。本项仅覆盖上述指定 Rule 与 `true` 配置，不推广到全部 Rule，也不据此保证 `false` 配置永不消失；不把它解释为持续时间正常到期。证据：迂回表第33条 P898/X1050，当前用户于2026-11-03确认按此边界补入；非本轮新增实机测试。
- 英雄侧仅战斗外净效果的两 Buff 组合：一条 `always` Buff 常驻提供数值，另一条采用已确认的仅战斗内条件（`monster_type_count_min`，数量1、空类型字符串、取反）提供等量反向数值。两条 Buff 均存在，且该属性与结算方式确能精确抵消时，战斗内净效果为0，战斗外保留常驻效果。这是两条 Buff 的净值组合，不是新增的战斗外 Rule，也不推广为任意属性均可相抵；战斗内条件的英雄侧、常规有怪物且空类型无匹配等边界仍适用。读档导致组合成员消失的风险须另按 P898 核对，不由净值关系保证生命周期稳定。证据：迂回表第33条 P895/X1046–P897/X1048，当前用户于2026-11-03确认按此边界补入；非本轮新增实机测试。
- 英雄侧仅战斗内成立的条件组合：`rule_type: "monster_type_count_min"`，`rule_data.float: 1`，`rule_data.string: ""`，`is_false_rule: true`。在原表所述常规有怪物且空类型无匹配的战斗场景中成立；脱战后缺少检测对象，返回 `null`，取反也不激活。该结论不推广到怪物持有者，也不保证战斗中已无怪物等特殊窗口的表现。这里的空字符串用于怪物类型匹配，不是技能 ID、职业 ID 或怪物名称本地化。战斗外两 Buff 抵消方案和读档移除风险须按各自完整边界另核，不能由本项自动保证。证据：迂回表第33条 P888/X1038、P891/X1041–P893/X1043，当前用户于2026-11-03确认按此边界补入；非本轮新增实机测试。
- 使用限制：偷取仍不建议使用，可能误偷不该被偷的 Buff，只有严格受控环境才可自由使用。原表的标志物检测方案：用 `monster_type_count_min` 控制的减益施加率 Buff 在怪物身上暂存标志；该 Rule 在怪物持有者侧不激活，因此不改变该怪物对应施加率。需要检测时，将该 Buff 偷取到英雄身上，并在特定技能期间临时召唤对应 Size-0，使条件在英雄侧参与检测。保留原表偷取／真驱散的方案背景，不称绝对稳健，也不覆盖当前优先 Buff ID 定向驱散的要求；不能据此断言普通环境可直接照搬黑圣物完整实现，连续 set 后计数等已有例外仍须适用。标志物只是用途，Buff 原有性质不变；这里的两侧差异来自 Rule 的既有持有者范围。证据：迂回表第32条 P882/X1030，当前用户于2026-11-03确认按此边界补入；非本轮新增实机测试。
- 统计当前仍在场上的全部怪物中，`monster_type` 与 `rule_data.string` 相符的单位数量；数量达到 `rule_data.float` 时有效。
- **普通情况下，该统计会明确包含处于死而不僵状态、但仍留在场上的匹配怪物，包括死而不僵的 Size 0。** 判断关键是单位是否仍在场，而不只是其当前是否处于存活状态；“死亡”不等于已经从怪物计数中离场。
- 常规结束回合技能中，若中途召唤并击杀 Size 0，该 Size 0 可能进入“死而不僵”状态：状态为死亡但仍在场，后续普通 `spawn` Effect 仍可执行，但召唤与对自身的 set 变身被阻断；未落入连续 set 检测异常的普通情形下，仍会被本 rule 统计。
- 知识库编写者2026-09-19补充：连续 set 变身后的 size-0，绝大多数情况下无法被 monster_type_count_min 正常检测；黑圣物存在使用且生效的案例，但其他人无法复刻。保留例外，不写成绝对失效，也不得将个例当作可靠通用写法。
- 该限制针对被计数对象连续 set，与 Rule 持有者的阵营限制是不同维度；普通仍在场/死而不僵的 size-0 计数结论不能直接外推到连续 set。失败的精确次数、返回值和原因以及成功个例条件未知，不假定取反可修复。详见专题28连续 set 检测例外。
- `rule_data.float` 写 `0` 时，该 rule 永远不会返回 true；安全创作时必须填写大于等于 `1` 的最小数量。
- 游戏中的尸体本质上是性质特殊、怪物类型为 corpse 的怪物实体，不应把它理解为脱离怪物系统的常规尸体对象；是否被本 rule 统计取决于 `rule_data.string` 是否匹配其怪物类型。
- 该 Rule 作为怪物侧 Buff 的持有者时始终不生效；这不否定它作为英雄侧 Buff 的条件向 Rule，或作为目标/调用流程中的怪物数量条件使用。
# 作用范围
- `通用型（条件型）` rule；分类决定它在施术、受术或通用条件上下文中的可用性。
- 当前用户于2026-11-03补充的理论模型：所有 Rule 都有各自的有效判定范围；范围外返回 `null`，无论是否取反均表现为不生效；范围内返回普通 `true` 或 `false`，二者可由 `is_false_rule` 相互翻转。这里的范围是对象、调用方、目标、时序及必要状态所组成的有效判定上下文，不是 `rule_data.float` 的数值阈值。具体范围须逐 Rule、逐调用上下文查证；不能把缺失上下文当作普通 `false`，也不能从本模型补造某条 Rule 的具体范围或声称55条均已逐项实测。
- 本词条中阈值、ID 或状态的取反关系，均以处于有效判定范围内为前提；分类和参数合法性不能代替具体上下文边界。
# 引擎行为（重要）
- 每一种 Rule 的一次判定都可能返回 `true`、`false` 或 `null`。`null` 表现为不激活；`is_false_rule` 只能翻转普通 `false`，不能把 `null` 翻转为 `true`。具体何时返回 `null` 仍须按该 Rule 的判定目标和调用上下文确认。
- 语法合法、规则求真、stat_type 能否在该时机生效是三个不同问题。
# 常见错误
- 忘记同时提供 `rule_data.float` 与 `rule_data.string`。
- 把 `is_false_rule` 取反当成能修复所有 null 上下文。
- 对只能使用通用型 rule 的 stat_type 配置进攻型/防御型 rule。
