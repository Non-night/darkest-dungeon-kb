skill
# 分类
通用型（条件型）
# 参数类型
`rule_type` 固定字符串；配套 `rule_data.float` 为数值，`rule_data.string` 为字符串。
# 参数约束
- 该值已收录为 rule_type；float/string 的实际含义仍应按原版案例与社区说明填写。
- `is_false_rule: true` 只在有效判定范围内翻转普通 `true`／`false`；范围外的 `null` 不会被翻转为 `true`。
# 固定值 / 参数候选
- float 示例：`0`
- string 示例：`skill name ID`
# 语义
- 对某个技能有效（非skill期间时，修饰的buff不会工作）（对反击技能不生效）
- 关于skill rule的范围以及涉及rule的null用法的相关内容，详见《暗黑地牢迂回代码整理》

- “标志物”是用途而非性质：所有标志物都保留其原有机制性质，不能因称作标志物而获得额外的隔离、免疫、无副作用或专用判定规则。减益概率标志物本质上仍是减益概率，在相同条件下与常规用途的减益概率遵循完全一致的机制；其他标志物同理，须按实际字段、属性、来源、目标、时序与生命周期判断。本原则不补造任何具体属性尚未确认的行为；例如 skill Rule 响应期内增伤、减伤等非概率属性的同类影响仍未知。依据：当前用户于2026-11-03主动补充的通用原则，非本轮新增实机测试。
- 概率属性的响应期交互：由 `skill` Rule 控制的概率属性增减，不限于跨侧减益筛选标志物，也包括常规用途；在相应技能有效期间，该单位反击或受击反馈所用的对应概率也会受其影响。减益施加率标志物只是其中一个具体例子，其他概率修正也应按实际调用的相应概率判断。是否构成不期望的干扰取决于设计用途，不能仅因使用 `skill` Rule 就一概判为风险。增伤、减伤等非概率属性是否存在同类影响，当前用户表示未知；不得据此扩展为所有 stat_type 均受影响。反击本身不能被 `skill` Rule 识别的边界不变。本项不确认 P882 替代方案或通用修复。证据：迂回表第32条 P881/X1028及当前用户2026-11-03确认后的范围补充；非本轮新增实机测试。 2026-11-17补充边界：上述普通用法和历史概率属性交互不能直接证明effect_chance在skill Rule下也能正常工作；九封报告了该组合的概率修饰失效，现按暂行社区测试反馈单独记录，不作为skill Rule整体失效的绝对结论。详见本专题“effect_chance 配合 skill Rule 的概率修饰失效（暂行测试反馈）”及Sources/effect_chance_skill_rule_20261117.json。
- 历史测试的有效判定期间全场性（2026-11-08限定：不据此推定释放前所有单位同时激活，也不填补本次释放期间非目标单位行为的未测项，详见Sources/negative_stealth_skill_hover_20261108.json）：攻击者使用技能 A 的有效 `skill` Rule 判定期间，全场敌我单位身上基于 A 的 `skill` Rule 均生效，包括未被该技能或其 Effect 涉及的单位。这里说明有效判定期间的范围，不等同于技能结束后的残留范围；残留的施加、清除与暴击特例仍须分别核对，第31条暴击残留究竟仅敌方还是敌我双方的范围差异仍未确定。反击本身不能被 `skill` Rule 识别的边界不变。证据：迂回表第32条 P878/X1023，当前用户于2026-11-03确认按此边界修正；非本轮新增实机测试。
- 攻击者 X 使用技能 A 的有效判定期间，目标 Y 身上基于 A 的 `skill` Rule，在 Y 对 X 反击或触发受击反馈时仍然有效；此时判定的技能 ID 仍是 X 的 A。反击本身不能被 `skill` Rule 识别，不能将这条响应期间的有效性解释为识别到了 Y 的反击，也不能改用 Y 的反击技能 ID 来说明本项结论。本项说明响应期间仍按技能 A 判定；有效期间的全场性见 P878，不能与技能结束后的残留范围混同。证据：迂回表第32条 P864/X1004–P874/X1016；当前用户于2026-11-03确认，并补明“反击是不能被skill rule识别到的”；非本轮新增实机测试。
- 普通用法：`skill` Rule 按 `rule_data.string` 中的技能 ID 限定 Buff 的生效条件，可用于指定技能的条件增益；反击本身不能被 `skill` Rule 识别。施术者侧选中技能、尚未释放时就进入判定期；不能外推为所有Buff持有者同时激活。怪物持有英雄技能条件Buff时，释放前仅选中技能不激活，须选中技能并悬停该怪物碰撞箱；释放期间非目标单位是否激活、英雄持有怪物技能条件Buff时何时开始激活均未确认，见Sources/negative_stealth_skill_hover_20261108.json。不能仅因使用了 `skill` Rule 就将普通技能增益列为风险项，或要求增加 AD、Size-0、真伤清残留。
- 风险按属性、调用时序与设计用途判断：弱魔免／反向弱魔免须审查残留导致的失效；由 `skill` Rule 控制的概率属性增减，无论标志物还是常规用途，均须考虑其对反击／受击反馈中对应概率的影响。是否构成问题取决于是否符合设计，不能仅因使用 `skill` Rule 就一概判为风险。增伤、减伤等非概率属性的同类影响仍未知，不据此泛化。涉及 AD、跨行动残留或清除时点时，按对应生命周期事实及来源条件判断。
- 受术者在 `queue false`、`queue true` 或 AD 时序内第一次承受任意数值的真伤时，在该次真伤结算完毕之后，清除其残留的受术者侧 `skill` Rule 状态。这条不适用于施术者；施术者当前技能内的判定及其 AD 覆盖仍按已收录的来源条件处理。不推广到 AWR，也不据此保证任意零真伤写法都能进入结算或没有副作用；微真伤修复的具体写法须结合第154条完整条件核对。证据：迂回表第31条 P855/X992–P856/X993；当前用户于2026-11-03确认，非本轮新增实机测试。

# 作用范围
- `通用型（条件型）` rule；分类决定它在施术、受术或通用条件上下文中的可用性。
- 当前用户于2026-11-03补充的理论模型：所有 Rule 都有各自的有效判定范围；范围外返回 `null`，无论是否取反均表现为不生效；范围内返回普通 `true` 或 `false`，二者可由 `is_false_rule` 相互翻转。这里的范围是对象、调用方、目标、时序及必要状态所组成的有效判定上下文，不是 `rule_data.float` 的数值阈值。具体范围须逐 Rule、逐调用上下文查证；不能把缺失上下文当作普通 `false`，也不能从本模型补造某条 Rule 的具体范围或声称55条均已逐项实测。
- 本词条中阈值、ID 或状态的取反关系，均以处于有效判定范围内为前提；分类和参数合法性不能代替具体上下文边界。
# 引擎行为（重要）
- 每一种 Rule 的一次判定都可能返回 `true`、`false` 或 `null`。`null` 表现为不激活；`is_false_rule` 只能翻转普通 `false`，不能把 `null` 翻转为 `true`。具体何时返回 `null` 仍须按该 Rule 的判定目标和调用上下文确认。
- 语法合法、规则求真、stat_type 能否在该时机生效是三个不同问题。
# 常见错误
- 忘记同时提供 `rule_data.float` 与 `rule_data.string`。
- 把 `is_false_rule` 取反当成能修复所有 null 上下文。
- 对只能使用通用型 rule 的 stat_type 配置进攻型/防御型 rule。
# 代码案例

{"rule_type":"skill","is_false_rule":false,"rule_data":{"float":0.0,"string":""}}
