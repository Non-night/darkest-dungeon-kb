disable_combat_skill_attribute
# 分类
Buff `stat_type`
# 参数类型
固定字符串；配套 `amount` 为数值，`stat_sub_type` 为字符串。
# 参数约束
- `stat_sub_type` 必填，且必须来自固定候选表。
- 只能使用通用型（条件型）rule；不能在战斗过程中瞬时生效。
# 固定值 / 参数候选
- `heal`
- `buff`
- `debuff`
- `bleed`
- `poison`
- `stun`
- `tag`
- `stress`
- `move`
- `guard`
- `daze`
# 语义
- 禁用治疗
## 存档数字 ID 与 amount 默认分类
- 存档 `stat_type` 数字 ID：`33`。
- `amount` 正值：减益；负值：增益；零值：增益。
- 这是默认增益/减益分类，不直接说明效果对游戏玩家有益或有害；Buff 型 DOT 的分类边界见[完整数字 ID 与 amount 分类表](../stat_type_amount_classification.md)。
# 作用范围
- `.buff_type disable_combat_skill_attribute` 与 buffs.json 的 `"stat_type":"disable_combat_skill_attribute"` 对应。
# 引擎行为（重要）
- 这一部分都是禁用相关的技能所用的代码，比如禁用治疗效果，则携带该效果的单位的所有具有治疗效果的技能都会被禁用，同时，这部分也可以利用其相关机制给技能设置冷却机制，一般来说选择自身所没有的效果来实现技能冷却（如daze等）
  注意：
  同种禁用的buff数值（amount）之和大于0时，禁用效果才能生效，反之，数值之和小于0时不生效，因此正负不同数值的同类禁用可以互相抵消，计算效果如下：
  1、当敌方对英雄侧施加一个数值为7的禁用治疗效果时，我方无任何反向禁用效果，则7+0=7＞0，禁用治疗效果生效；
  2、当敌方对英雄侧无任何禁用治疗效果时，我方存在一个-10的禁用治疗效果，则0+（-10）=-10≤0，禁用治疗效果不生效（免疫）；
  3、当敌方对英雄侧施加一个数值为7的禁用治疗效果时，我方存在一个-10的禁用治疗效果，则7+（-10）=-3≤0，禁用治疗效果不生效（免疫）；
  综上所述：
  当禁用效果合值小于等于0时，禁用失效（虽然游戏增减益图标上依然显示禁用减益）；
  当禁用效果合值大于0时，禁用生效。
- 禁用式冷却采用 `after_round` 时，若禁用 Buff 跨战保留且未被其他机制提前移除，可实现脱战不消耗冷却，重新进入战斗后按整轮继续扣减。此处仅说明基于禁用 Buff 的冷却用途，不推广到怪物 AI 自带冷却，也不提供完整实现。证据：迂回表第35条 P911/X1066，当前用户于2026-11-03确认按此边界补入；非本轮新增实机测试。
- 当前用户明确补充（2026-09-24）：在绝大多数情况下，不应设计或使用 `stat_sub_type` 为 `buff` 或 `debuff` 的禁用增益技能/禁用减益技能，因为这极易误伤自定义文本。只有确有必要且已检查自定义文本影响范围时才考虑例外；该警告只针对 `buff`/`debuff` 两个副类型，不推广到其他禁用技能属性。
# 常见错误
- 百分比型 amount 忘记使用小数（例如 30% 常写作 `0.3`）。
- 固定加减与倍率乘除顺序不同，极端负值可能出现反向增长等异常结果。
- `stat_sub_type` 缺失、误拼或错误地填写了不属于该主类型的值。
# 代码案例
```json
{"stat_type":"disable_combat_skill_attribute","stat_sub_type":"heal","amount":0.1}
```
