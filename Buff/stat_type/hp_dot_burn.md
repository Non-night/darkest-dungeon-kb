hp_dot_burn
# 分类
Buff `stat_type`
# 参数类型
固定字符串；配套 `amount` 为数值，`stat_sub_type` 为字符串。
# 参数约束
- 该类型没有副类型；JSON 中字段仍必须存在，并写为空字符串 `""`。
- 可用 rule 分类仍应结合具体 stat_sub_type 和引擎上下文判断。
# 固定值 / 参数候选
- 无固定副类型候选。
# 语义
- Buff 型燃烧 DOT。
## 存档数字 ID 与 amount 默认分类
- 存档 `stat_type` 数字 ID：`88`。
- `amount` 正值：不划为增益或减益（Buff 型 DOT）；负值：不划为增益或减益（Buff 型 DOT）；零值：不划为增益或减益（Buff 型 DOT）。
- 这是默认增益/减益分类，不直接说明效果对游戏玩家有益或有害；Buff 型 DOT 的分类边界见[完整数字 ID 与 amount 分类表](../stat_type_amount_classification.md)。
# 作用范围
- `.buff_type hp_dot_burn` 与 buffs.json 的 `"stat_type":"hp_dot_burn"` 对应。
# 引擎行为（重要）
- 使用警告（知识库编写者明确要求，2026-11-01）：极度不建议使用 Buff 型燃烧；保留机制与 amount 0.99 用途不代表推荐使用。对群偷取后只有正在发生结算的那个燃烧可与后续燃烧合并，不能解决异常；该例外不推翻 Buff 型燃烧不合并的独立结论。知识库编写者补充并限定（2026-11-01）：这里的“对群偷取”专指 Effect 自身的目标写为群体类型，不是按技能是否 AOE 判断；AOE 技能逐个目标调用对单偷取应无此处的群体偷取问题。避免对群偷取燃烧的建议针对以转移燃烧并继续正常发挥其燃烧作用为目的的用途，不是对所有群体偷取用途的禁令。若目的只需要“转移后存在”的状态，或另有不依赖正常合并与燃烧结算的目的，可结合具体需求接受。Agent 必须根据实际目标、相关机制及当前用户要求自行判断，不能将下列例子当作用途白名单，也不能把可接受某用途推广为群体偷取已无异常。例如，size0 对英雄全体偷取燃烧后检测自身有无燃烧，或者先对群偷取再偷取自身以驱散，均可接受；后者大多数情况下不如直接对群治愈燃烧。这些只是说明性例子，不穷尽可接受用途。
- 官方 Fire’s Edge 表格将其列为 Buff 型燃烧；当前扫描的官方 DLC Buff JSON 未找到直接的 stat_type=hp_dot_burn 实例。
- 知识库编写者在本次会话补充（入库日期 2026-10-17） 确认：Buff 型燃烧不会与其他燃烧合并。多个未合并燃烧在回合结束时只触发最先施加的一个，并只衰减该燃烧的层数；`.dmg_per_burn_stack` 能否读取未合并燃烧尚未确认。
- 知识库编写者本次会话确认：Buff 型燃烧的 amount 在 `[0, 1)` 时，回合结束播放燃烧生效音效，但不造成伤害、不减少层数，也不因燃烧结算使该 Buff 型燃烧消失；其正常持续时间仍可到期。先施加 amount 为 `0.99` 的 Buff 型燃烧，可在其持续期间阻止后续燃烧造成伤害与衰减；Buff 栏将该燃烧显示为 0 层。
- Buff 型燃烧没有 Effect 型燃烧在施加时或随后 Update 时被强制设置为 `duration: 10000` 的特性。
- 知识库编写者提供无夜2026-11-05 15:06–15:28聊天及范围澄清：Effect型与Buff型DOT的量为正或负均可存在；最终持续时间为负则不可存在。合法性看修正后的最终量与最终持续时间，不看初始值；修正Buff的影响范围保持已有规则不变。Effect型DOT另有描述观察：初始负量可存在，但施加该DOT的Effect不显示该DOT描述；初始负持续时间不可存在，但施加该DOT的Effect仍显示该DOT描述；这两条描述观察按聊天原述保留，不将“初始”改写为描述生成也必看最终值。任何类型的Buff型DOT均不由施加它的Effect生成该DOT的自动描述，因此无法以此出现在技能自动描述中。这里的“描述”明确指施加该DOT的Effect是否显示描述，不指持有者身上的状态说明或图标，也不限制手动自定义文本。 来源：Sources/dot_legality_description_20261105.json。
# 常见错误
- 百分比型 amount 忘记使用小数（例如 30% 常写作 `0.3`）。
- 固定加减与倍率乘除顺序不同，极端负值可能出现反向增长等异常结果。
- `stat_sub_type` 缺失、误拼或错误地填写了不属于该主类型的值。
